# 入力元中立の支出照合 — 30思考法レビュー

対象: `feat/35-source-neutral-spending` / Issue #35

## 思考リセット

「freee=事業、Money Forward=家計」という既存の近道を前提にせず、中心対象を「実際に発生した1回の支出」と置き直した。既存canonical、取込取消・期間/種別削除・全件入れ替え・30日undoは削除せず、読み取り投影だけを追加した。

第一印象の主要リスクは、原本別の無条件合算による二重計上、曖昧一致による実支出の消失、MF-only事業支出の見落とし、freee個人支出の経費混入、サブスク候補のfreee固定、freee複合行の空日付棄却だった。

## 統合した改善

1. canonicalを変えない`ExpenseProjection`を唯一の照合規則とし、API・サブスク・AI候補で再利用した。
2. 代表画面を帳簿確定・未記帳・実質支出の比較と次の一手に再構成した。
3. 曖昧候補を自動除外せず、理由と事実を見せて既存の公私仕分け・取込履歴へ戻した。
4. freee複合行は直前の有効な同収支区分だけを継承し、壊れた文脈を次行へ伝播させないparserにした。
5. 個別明細/取込/全件の削除を複製せず、既存の確認指紋・writer fence・30日undo経路を案内した。

## 残る安全制約

- 同日・同額・同用途・同支払先の別購入が各入力元に1件ずつある場合は共通IDがなく識別不能で、現版は決定的な1対1として扱う。
- MFに安定IDがない明細と分割明細は自動照合しない。
- 曖昧候補の確認結果は永続ペアにせず、原本・分類の修正後に再導出する。
