# T2. 体験設計 — 照合作業場の改善

## 代表成果物と主要ジャーニー

最頻業務は「対応が必要な行を1件判断する」。代表画面は `/analysis/reconciliation` の3列マスタ詳細です。

対応キューを選ぶ → 中央一覧で1行選ぶ → 右詳細で根拠を確認して処理する（3操作・30秒以内）。

- **ピーク**: 一覧で選んだ瞬間に、MF・freee・一致理由・一致度が右詳細へ揃い、迷いが消える。
- **エンド**: 「保存しました」と `actionRequiredCount` の減少、直前操作の Undo を同じ文脈で返す。

## 情報設計

| 列 | 役割 | 主な内容 |
|---|---|---|
| 左 | 対象を絞る | 折りたためる絞り込み、対応キュー、確認のみ |
| 中央（主役） | 比較対象を選ぶ | 状態、日付、MF内容、金額、freee候補、差額、一致度 |
| 右 | 根拠を見て決める | 両取引の詳細、一致理由、主要操作、直前操作と Undo |

下段は左=`mfOnly`、右=`reviewRows` の代表行だけを示す読み取り専用プレビューです。操作は中央一覧と右詳細に集約します。`unmatchedFreee` は表示しません。

### モバイルで減らす情報

375〜768pxでは左を折りたたみ、中央は「状態・内容・金額」を優先し、日付は421px以上では一覧、420px以下では選択行の詳細で確認できるようにします。freee候補・差額・一致度も選択行の詳細で確認できるようにし、右詳細を一覧直後へ縦積みします。列比較が必要な表は、ページ全体をはみ出させず、名前付き・フォーカス可能な枠内で横スクロールを許可します。下段は件数・代表行・導線だけにし、固定選択バーは safe-area を避けます。状態、主要操作、Undo は削りません。

## 6状態

| 状態 | 画面の振る舞い |
|---|---|
| 理想 | KPI→キュー→一覧→詳細→操作が一画面でつながる |
| 空 | 「対応が必要な取引はありません」を示し、MFのみは確認専用、完全にデータが無ければデータ取込を1 CTAで案内 |
| ローディング | 0.4秒超で KPI と3列の骨格スケルトン。既存表示を消して白紙にしない |
| 部分 | 1〜2件でも3列幅を崩さず、未選択時は中央の最初の行を案内。下段に無い側は理由と導線を出す |
| エラー | 何が失敗したか、保存済みデータは無事か、再試行を表示。待てば直るエラーだけ再試行を強調 |
| オフライン/低速 | 直近の読取キャッシュを閲覧可にし、書込は送らず選択を保持。「接続後に再試行」を示す |

## 権限・データライフサイクル

認証済み本人だけが閲覧・判断・取消できます。取込原本は編集せず、判断・除外を別レコードで保持します。全期間で照合した後に選択期間へ投影し、サイドバーと月次クローズは全期間の `kpi.actionRequiredCount` を使います。

## マイクロコピーと動き

主要 CTA は「同じ取引として照合」「別の取引として処理」。MFのみは「対応不要」と理由を併記します。行選択は背景と `aria-current`、保存結果は `role=status`、失敗は `role=alert`。入場アニメーションは使わず、focus・pressed・処理中をトークンで示し、reduced-motionでも意味を維持します。
