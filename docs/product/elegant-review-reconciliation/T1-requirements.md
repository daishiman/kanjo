# T1. 要件定義 — 照合作業場の改善

**作成日**: 2026-09-16 / **サイズ**: S（1画面・単一の照合ユースケース）

## 事実・仮説・判断

| 区分 | 内容 | 根拠 / 検証 |
|---|---|---|
| 確認済みの事実 | 現行画面は一覧が長く、右側が空になる状態がある。目標画像は KPI、左キュー、中央一覧、右詳細の3列を同時に示す | 提供画像と `Reconciliation.tsx` |
| 確認済みの事実 | 状態は5つ。MFのみは対応不要。対応必要総数は `kpi.actionRequiredCount`、下段は `mfOnly` / `reviewRows` のプレビュー | `specs/spec-reconciliation.md` 正本 |
| 可逆な仮説 | 最頻業務は「対応キューを選ぶ→1行を比較→照合または別取引を決める」で、30秒以内に終える価値が最も高い | preview の操作計測で検証 |
| 本人しか決められない境界 | なし。外部送信・本番データ変更・新しい課金は行わない | 作業スコープ |

採用案は、候補一覧と選択行の詳細を主役にした3列マスタ詳細です。別画面へ分割する案は比較の往復を増やし、巨大な1表へ統合する案は根拠と操作を見失うため採用しません。

## 課題と成果

> 個人事業主が月次確認時に、対応が必要な取引と判断根拠を同時に見られず、どこから何を処理するか迷う。

| 指標 | 現在値 | 目標値 | 計測方法 |
|---|---:|---:|---|
| North Star: 対応必要行を開いて判断完了する時間 | 未計測 | 中央値30秒以内 | `reconciliation_row_opened` → `reconciliation_action_completed` |
| 件数整合の不一致 | 既知の複数定義あり | 0経路 | 同じ投影scopeの `actionRequiredCount` を契約テストで比較 |
| 誤操作ガードレール | 未計測 | 10分以内の undo 率5%以下 | action / undo の匿名化イベント |
| モバイル横はみ出し | 提供画像では発生 | 0px | 375 / 768 / 1024 / 1280 / 1600px の描画検査 |

## ユーザーと to-be

| 分類 | 誰 | 利用頻度 | 習熟度 |
|---|---|---|---|
| 主要 | 帳簿と口座を照合する個人事業主 | 月次、差異発生時 | 会計用語は分かるが判定規則は覚えない |
| 管理 | 同じ利用者（取込・仕分けも担当） | 月次 | 自分で復旧できる導線が必要 |

as-is: 長い一覧を見て、空の詳細領域や別画面を行き来する。  
to-be: 対応キューを選ぶ → 候補を1行選ぶ → 右詳細で根拠を確認 → 主要操作を行う → 件数減少と Undo を同じ場所で確認する。

## 体験・機能要件

- 中央一覧と右詳細を常に因果で結び、主要操作は詳細の1か所に置く。
- 5状態と対応不要を文字で示し、色だけに頼らない。
- 全期間で照合してから期間投影し、画面間の総数は `actionRequiredCount` だけを使う。
- 下段は読み取り専用プレビューとし、重複する第2のキューを作らない。
- 狭幅では補助情報を畳み、一覧→選択行詳細→主要操作を縦に保つ。ページ全体は横へはみ出さず、比較表だけをラベル付きの枠内で横へ操作できる。

## Non-Goals

1. freee / MoneyForward への書き戻し。  
2. 一致アルゴリズムの機械学習化や自動確定範囲の拡張。  
3. 総収支・マトリクス・推移・診断画面の全面改修。  
4. `unmatchedFreee` を新しい下段キューとして表示すること。

## 制約

実取引データは公開文書・fixture・コミットへ入れない。検証は `samples/` と匿名化 seed のみ。取込値は読み取り専用で、保存するのは利用者の判断・除外・操作履歴だけとする。

## 保留

`unmatchedFreee` は現行 web 未使用。削除は後方互換への影響を確認する別カードで扱う。
