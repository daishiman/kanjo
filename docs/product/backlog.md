## 次の候補(優先順)

- [品質] ID列の無い旧MF exportへ行順非依存の安定IDを導入する — 現在は安全性を優先して保証を限定し、行index合成IDと順序依存を仕様・テストへ固定した。既存手動編集との移行規則が必要
- [機能] 明細の名義を「口座」から判定するため、本番の MF 明細を `保有金融機関` 列入りのエクスポート(2026年1〜8月分)で取り込み直す — 現在の本番データ(2026-07 のみ)は列が無い時期の取込で、名義が「未設定」になる。運用作業のため依頼者の再取込待ち
- [機能] 事業の科目に freee の `品目` を中項目として持たせる — `品目` は任意入力で現在は取込対象外。決算書の科目(勘定科目)だけで足りるか実使用を見て決める

- [機能] 取込履歴に「誰が・どの画面から」の監査情報を持たせる(参考要件の監査履歴) — 1人運用のため優先度低。削除・上書きの監査記録は `specs/import-deletion-and-override-reapply.md` が包含するため、本行はそれ以外(取込の実行経路の記録)だけを指す
- [品質] AI分析: 同じ期間で2回生成して要点・優先度のばらつきを測る(第3版の再現性ルールが効いているか) — preview ではAIを走らせられないため、本番で実レポートが2本溜まってから
- [機能] AI分析: 期間の粒度を四半期に丸めるのは37ヶ月以上の期間のみ。ローカルには11ヶ月分しか無く preview で四半期表示を目視できていない(単体テストで固定済み) — 本番に3年分が溜まってから本番URLで確認
- [機能] AI分析: 貸借対照表(BS)観点の追加 — 取込データは損益(収入・支出)だけで、資産・負債の残高(口座残高・未払金・借入)を持たないため現状は算出不能。口座残高の取込(MF 資産データ)を追加してから
- [UX] AI分析: 指示文をコピーした時刻・貼り付け先(Claude Code / Codex)の記録 — 1人運用のため優先度低
- [機能] AI分析: Codex のサンドボックスは既定でネットワーク不可の場合があるため、その旨と「データを表示/結果を貼り付ける」の案内をスキル側にも載せる(現状は SKILL.md に一文) — 実際に Codex で1回回してから文言を固める
- [品質] AI分析: 届いたレポートの品質評価(推測の混入・データ不足の書き漏れ)を人が採点して SKILL.md を育てる — 数本溜まってから
- [機能] 証憑: freee 仕訳(事業の取込明細)にも添付できるようにする — freee 側に再取込を跨いで安定するIDが無く、添付先の同定規則を決める必要があるため。現金の記帳とMF明細で運用してから
- [機能] 証憑: 添付画像から日付・金額・支払先を読み取って記帳に埋める(OCR) — 外部APIか大きな依存が要る。まず手入力+添付の運用で頻度を見てから
