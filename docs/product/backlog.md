# 残課題リスト

「やらないこと」ではなく「順番を後にしたこと」。1件1行。書式: `- [分類] 内容 — 後回しにした理由`。
上から着手候補順。完了したら行を消し、PRで参照する。

## 次の候補(優先順)

- [機能] 明細の名義を「口座」から判定するため、本番の MF 明細を `保有金融機関` 列入りのエクスポート(2026年1〜8月分)で取り込み直す — 現在の本番データ(2026-07 のみ)は列が無い時期の取込で、名義が「未設定」になる。運用作業のため依頼者の再取込待ち
- [機能] 事業の科目に freee の `品目` を中項目として持たせる — `品目` は任意入力で現在は取込対象外。決算書の科目(勘定科目)だけで足りるか実使用を見て決める

- [機能] 仕分け画面に「月別の仕分けサマリー(事業/個人の件数・金額)」と「仕分けの考え方」の説明枠を追加する(参考実装にあり未実装) — 今回は見え方の修正を優先。集計は既存の /transactions summary で取れるため画面追加のみ
- [機能] 現金の記帳と freee の仕訳が同じ支払いを指すとき(現金払いを後から freee にも登録した場合)の二重計上を検知する — 同日・同額・同科目の突合で警告できるが、まず現金の記帳の実運用で頻度を見てから
- [機能] 現金の記帳を統合JSONの復元(POST /restore)にも含める — 夜間バックアップ(R2)には `cashEntries` として含めているが、復元側は取込明細のみ。復元は初期移行でしか使わないため
- [機能] 取込で「月の途中までのファイル」を検知したとき(件数減の警告)、自動で前回の内容を残す選択肢を出す — 現状は警告表示のみ。元のファイルを取り込み直せば戻せるため
- [UX] 明細一覧に「手入力(現金)」バッジと支払手段(現金/口座/カード)での絞り込みを追加する — 現金の明細は口座名「現金」で見分けられるため初回は見送り。明細が増えて探しづらくなってから
- [機能] 現金の記帳にレシート・領収書の画像を添付できるようにする(R2 保管) — 保管先と閲覧画面の追加が必要な別機能のため。まずはメモ欄で運用
- [UX] 取込履歴に「この取込をやり直す(再取込)」ボタンを付ける — 重複スキップはデータを何も変えないため取り消し不要。誤って「取り込み直す」を使った場合も元ファイルの再取込で戻せるため
- [UX] 取込画面で失敗したファイルを「再取込」ボタンから同じ枠へ戻せるようにする — 現在は理由を読んでファイルを出し直す運用。失敗理由の表示で当面の迷いは解消したため
- [機能] 取込履歴に「誰が・どの画面から」の監査情報を持たせる(参考要件の監査履歴) — 1人運用のため優先度低
- [性能] 本番URLで Core Web Vitals を計測し、フォント(Zen Kaku Gothic New 全ウェイト同梱)の読み込みを絞る — 配布物にサブセット外のフォントファイルが大量に含まれており初回表示が重い可能性。計測してから対処
- [UX] 家計・サブスクの表をスマホ幅でカード表示に切り替える — 現状は横スクロールで閲覧可能。実機で困ってから
- [機能] 予算サマリーに「編集中の下書き」を即時反映する — 現在は保存後に反映。誤解を招くなら対応
- [品質] AI分析: 同じ期間で2回生成して要点・優先度のばらつきを測る(第3版の再現性ルールが効いているか) — preview ではAIを走らせられないため、本番で実レポートが2本溜まってから
- [機能] AI分析: 図表を追加する(科目×月のヒートマップ、名義別の推移など) — まず固定8枚で運用し、読まれない図・欲しい図が分かってから入れ替える
- [UX] AI分析: 「2. 実行する」の依頼一覧で受信済みの行を畳む(最新の結果待ちだけ出す) — 検証で依頼を大量に作ると一覧が長くなるが、実運用は月1〜2件のため様子見
- [UX] AI分析: 図の折れ線・棒に触れたときの数値表示(ツールチップ)の文言を用語解説とそろえる — 現状は chart.js 既定の表示
- [機能] AI分析: 期間の粒度を四半期に丸めるのは37ヶ月以上の期間のみ。ローカルには11ヶ月分しか無く preview で四半期表示を目視できていない(単体テストで固定済み) — 本番に3年分が溜まってから本番URLで確認
- [運用] preview サーバー(`pnpm run preview`)は画面を作り直しても古いファイル一覧を配り続けるため、画面を直したらサーバーごと再起動する(`docs/` の手順に追記予定) — 開発時だけの話で利用者には影響しない
- [機能] AI分析: 貸借対照表(BS)観点の追加 — 取込データは損益(収入・支出)だけで、資産・負債の残高(口座残高・未払金・借入)を持たないため現状は算出不能。口座残高の取込(MF 資産データ)を追加してから
- [機能] AI分析: 統計指標の基準月数(現在6ヶ月)を設定画面から変えられるようにする — 実データ12ヶ月未満の運用で困ってから
- [UX] 用語解説: 表記ゆれの別名(例「損益分岐」「BEP」)を増やす — 実レポートの語彙が溜まってから
- [機能] AI分析: レポートの削除・アーカイブ、依頼(結果待ち)の取り消し — 期限24時間で自然に失効するため当面不要
- [UX] AI分析: 指示文をコピーした時刻・貼り付け先(Claude Code / Codex)の記録 — 1人運用のため優先度低
- [機能] AI分析: Codex のサンドボックスは既定でネットワーク不可の場合があるため、その旨と「データを表示/結果を貼り付ける」の案内をスキル側にも載せる(現状は SKILL.md に一文) — 実際に Codex で1回回してから文言を固める
- [品質] AI分析: 届いたレポートの品質評価(推測の混入・データ不足の書き漏れ)を人が採点して SKILL.md を育てる — 数本溜まってから

- [機能] サブスク: 登録した支払先について「この勘定科目のときだけ数える」を指定できるようにする — 現状は登録済み支払先を科目に関係なく合算(Amazonのような幅広い取引先を登録すると物販も混ざる)。困る取引先が出てから
- [機能] サブスク: 候補一覧に「サブスクではない」を記録して以後の候補から外す — 候補は上位20件に限られるため、まずは登録だけで運用
- [UX] サブスク: スマホ幅では候補の理由(採点根拠)を折りたたむ — 現状は横スクロールで閲覧可能
- [機能] freee 未決済(未入金・未払)の一覧: 支払期日/支払日/支払口座/支払金額を取り込み、期日超過を一覧にする — 調査済み(取引エクスポートに列あり)。サブスク整理の次に着手
