# 機能要件

プロトタイプ（単一HTML）で確定している画面構成を、実装単位の要件として整理したもの。

## 画面一覧

| # | タブ | 目的 | 主要ロジック |
|---|------|------|--------------|
| 1 | 概況 | 事業の月次トレンドと年次比較を俯瞰する | 3ヶ月移動平均、年換算、パレート分析（累積80%） |
| 2 | 増減マトリクス | 科目×月の全数を、金額／前月比／前年同月比で切替表示 | ヒートマップ濃度＝金額の平方根スケール |
| 3 | 統計診断 | 科目を固定費／準変動／スポットに分類し削減アプローチを変える | 平均・中央値・標準偏差・変動係数(CV)・zスコア・傾き |
| 4 | サブスク分析 | 最大コストであるサブスクをベンダー別に分解し重複を検知 | 中央値比 1.8倍かつ2万円超＝重複疑い、3倍超＝急増 |
| 5 | 公私仕分け | MF明細1件ずつを事業／個人に判定 | 優先順位＝手動指定 > キーワードルール（先勝ち）> 既定（個人） |
| 6 | 家計 | 事業立替を除いた純粋な個人収支を月次比較 | 仕分け結果を反映した再集計 |
| 7 | 予算管理 | 科目別の月次予算と予実差異 | 推奨値＝固定費は直近実績×0.95／スポットは全期間平均 |
| 8 | データ管理 | CSV/Excel/JSON の取込と統合JSONの書き出し | Shift-JIS/UTF-8 自動判別、同月上書き取込 |
| 9 | 指標ガイド | 統計を知らなくても判断できる読み方の解説 | 実データを差し込んだ動的な解説文 |

## 中核となる設計判断

### 1. 「記帳済み」と「未記帳」を区別する

売上が0の月が「本当に売上ゼロ」なのか「freeeに未記帳」なのかを区別しないと、平均も経費率も壊れる。

- `unrecordedExpMonths` — 経費が未記帳の月の集合。統計計算から除外し、マトリクスでは `—` を表示
- `revenueIdx()` — 売上 > 0 の月のみを売上統計の母集団とする
- `cashOverride` — freee未記帳だが銀行入金実績がある月の補正値（グラフに ◆ で重ねる）

### 2. 科目統一

2025年の「支払手数料」「通信費」は実態がサブスク費のため、取込時に「サブスク・通信」へ正規化する。この正規化をしないと期間比較が成立しない。

### 3. 公私仕分けは「管理用」であって税務上の記帳ではない

事業に仕分けた明細は別途 freee にも登録する必要がある。サマリーの「事業立替」額が、freee に登録すべき金額。

### 4. 上書き取込

同じ月のCSVを再投入したら、その月のデータは加算ではなく置換する。二重計上を構造的に防ぐ。

## 未実装・今後の課題

プロトタイプの「データ充足度」表に挙がっている不足項目：

- [ ] 2025/10以降の売上未記帳の解消（統計の前提）
- [ ] クレジットカード明細の取込（月26.9万円がブラックボックス）
- [ ] 取引先別の売上・案件単価（「増やすべき費用」の判断に必要）
- [ ] 資産・貯蓄残高の推移（現状はフローのみでストックが見えない）
- [ ] 家事按分ルールの設定（光熱費・通信費の事業割合）
