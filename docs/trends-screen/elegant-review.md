# 推移画面 エレガントレビュー

2026-09-16 に、既存の対策を正解とみなさない思考リセットから開始したレビュー記録。
本書は判断過程の監査証跡であり、仕様の正本ではない。利用者意図は
`system-spec/00-requirements-definition.md`、数値規則は `packages/core/src/trend-metrics.ts` を参照する。

## フェーズ1: 思考リセット

成果物は削除せず、現行画面・目標画像・実装・テストを初見として再読した。第一印象は次の4点だった。

1. 期間、見出し、分析ナビ、旧チャートが共通シェルや新画面と重複していた。
2. 主チャートが「収入・支出・純収支」を同時に答えず、canvas の枚数テストが意味の不足を隠していた。
3. 同名カテゴリ、比較月欠損、減少項目の符号で、表示と利用者の解釈がずれる境界があった。
4. `Trends.tsx` に取得、URL、集計の写像、描画、旧画面が集中し、変更理由が錯綜していた。

## フェーズ3: 改善と再検証

1. core/API: `category + side`、比較欠損の `null`、符号付き増減に加え、指標の視覚メタデータと `recommended` を正本化した。freee系4表の読込はtenant境界を保った共有helperへ集約した。
2. web: 保存値なしの初回を1年、明示全期間は保持。KPIを一体型要約帯へ統合し、8列表を比較不能時も維持、月選択をcompact controlへ変更した。出典を圧縮し、初期CTAから月→要因→明細を閉じ、新比較画面の旧判定重複を除いた。
3. test/docs: canvas枚数を系列意味へ置換し、8列、初期CTA、origin別文言、意味色、新指標、Spark欠損、初回期間、実描画fixtureのquery一致を固定した。
