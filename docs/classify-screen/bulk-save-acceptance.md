### 修正の前の結果 (不具合の発見)

- バーは『50 件選択中』。選択一覧は 48 件で、読み込み中の行は 0。存在しない 2 件は URL の sel から外れ、sel は 48 件になった。
- 一括指定の前の内訳は『24件を提案で保存』『24件は保存しません』『埋める値がありません』『変わる値がありません』『2件は見つかりません』で、ボタンは『選択した24件を保存』。
- 区分 (家計) を一括指定すると、内訳は『48件を一括指定で保存』『うち8件は『カテゴリなし』で保存』『2件は見つかりません』、ボタンは『選択した48件を保存』になった。式は 50 = 48 (保存) + 0 (外す) + 2 (見つからない) で成り立つ。
- 保存すると通知『選択した48件を保存しました。』が出て、提案の無い未整理 16 件は全件が確定に変わり、区分は家計になった。
- しかし 16 件の大項目は『未分類』のままだった。D1 の変更履歴 (source=bulk) にも、カテゴリ『未分類 / 未分類』が 16 行あった。

保存はできたが、spec の決まりと合わない。

- BR-01: 未整理は 一括指定 → 下書き → 提案 の順で埋める。今の値は埋める値の候補に入らない。
- 用語集の『カテゴリなし』: 埋める値のどこにも組が無いときに保存する値。
- UC-3: 括弧書きの「提案か今の値」は、未整理なら提案、確定済みなら今の値。

原因は core の解決関数 (`packages/core/src/classify-bulk.ts`) にあった。未整理の明細でも、提案が無いときは今の値の組を土台に使っていた。
未整理の今の値の組は取込値 (MF の大・中) で、人の判断も区分の候補の検査も経ていない。
その結果、取込値の『未分類』が人の確定した値として保存され、明細は「確定済み・未分類」になった。

### 選択の読み出しが 2 回に分かれること

1. 画面は表示中のページに無い key だけをサーバに問い合わせる。1 回目は表示外の 30 件と存在しない 2 件の、計 32 件を送った。
2. 応答の `missing` に入った 2 件を、画面が URL の sel から外す。
3. sel が変わると問い合わせの key の組 (queryKey) も変わるので、残りの 30 件をもう一度読む。

結果は同じで、不具合ではない。ただし 1 回目に読んだ 30 件を読み直す小さな無駄がある。
見つからない key を外しても queryKey が変わらない形にすれば 1 回で済む。本 feature の範囲の外なので、改善の候補として返す。

## 3. 1264px と 1280px (AC-22)

§2 の修正の後に `check:classify-screen` を走らせ直した実測 (単位は px、行は 50 行、列は左から 6 列)。
1264px と 1280px の列の最小幅は `[44, 92, 120, 96, 120, 84]` で、検査はどれか 1 列でも下回れば失敗にする。
URL の sel に 3 件 (うち 1 件は 2 ページ目) を入れた状態で測る。パネルの開閉はマウスの実クリックで行う。

| 幅 | 本体 (描画幅/画面幅) | 一覧 (パネル閉/開) | 表 (描画幅/枠の幅、パネル閉) | 列 (パネル閉) | 列 (パネル開) |
|---|---|---|---|---|---|
| 1264 | 1249/1249 | 553 / 373 | 560/553 | 44/92/120.8/96/123.2/84 | 44/92/120.8/96/123.2/84 |
| 1280 | 1265/1265 | 569 / 389 | 569/569 | 44/92/127.8/96/125.2/84 | 44/92/120.8/96/123.2/84 |

- 6 列は、パネルを開いても閉じても最小幅以上である。
- 本体の描画幅は画面幅と同じで、横のはみ出しは 0 である。
- パネルを閉じると一覧が 180px 広がる (1264px は 373→553、1280px は 389→569)。閉じ直すと元の幅に戻る。
- 1264px では、パネルを閉じても表が一覧の枠より 7px 広く、表の枠の中で横に送る。表は自分の枠の中でだけ横に送る作りなので、本体ははみ出さない。1280px では表と枠が同じ幅になる。
- キーボードで先頭から順にフォーカスを移すと、移った先は一括バーにも編集パネルにも覆われない (パネル閉で 114 か所中 114 か所、開で 131 か所中 131 か所が見える)。
- 一括バーの高さは 218px で、画面の高さ 900px の 35% 以内に収まる。

値は P06 の通し (evidence §2) と同じだった。修正は解決関数だけなので、画面の幅は変わらない。390px・768px・1024px も同じ段で合格した。
