# 改善リクエスト画面の思考リセット・30観点レビュー

対象はこの作業ツリーの `/improvement`、撮影パネル、core/API/DB の規則、現行仕様。参照画像は `design/FINAL-UI/images/20-improvement.png`。既存成果物は削除せず、最初に画面の中心対象を「改善リクエスト」、主作業を「その場を撮る→説明して送る→追跡し、開発へ渡す」と定め直した。参照画像は一覧・空状態・取得失敗を同時に載せた状態見本として読む。

実行順は、(1) 独立した俯瞰担当による思考リセット、(2) 論理・構造9観点、メタ・発想9観点、システム・価値・問題解決12観点の3担当による並列分析、(3) 画面、撮影処理、文書の3担当による並列修正、(4) 統合と再検証の1サイクルである。前段の結果が揃うまで次段の修正には進まなかった。

## 画像との照合

上段の作成、下段の一覧と詳細、撮影パネル、選択中バーを実ブラウザで確認した。900pxでも作成フォームと一覧・詳細を左右に置き、800px以下では読みやすさのため縦に積む。参照画像の空状態と読込失敗は、データがある一覧と同時には表示しない。共通シェルの幅・書体・色は [`docs/design-system.md`](../design-system.md) の正本に従うため、画像と画素単位の一致にはしない。

900px の参照画像は高さ1748px、匿名fixtureによる実画面の全ページ撮影は表示幅885px・高さ3062pxだった。表は左ペイン内で横スクロールする。参照画像の青系配色と広いサイドバーに対し、現行画面は緑青系トークンとアイコンレールを使う。デザイントークンの最小文字サイズと44pxの操作領域を保つため、密度差も残る。構成は照合したが、見た目は画像と完全一致ではない。
