# 推移画面の規則

`/analysis/trends` が使う計算規則と説明文の実行契約。利用者意図の正本は
`system-spec/00-requirements-definition.md`、実行される数値規則の正本は
`packages/core/src/trend-metrics.ts` (行の集合は `totalCashflowLedger`)。`specs/`・`architecture/`・
`tasks/`・`.dev-graph/` は投影であり、独立した第二の正本として扱わない。
**規則を変えるときは core・テスト・本書を同時に直す。**

規則を変えると落ちるテストは次の 4 本にある。

| テスト | 何を固定するか |
|---|---|
| `packages/core/test/trend-comparison.test.ts` | 比較期間・最大変化月・説明文・スパークライン・要確認・出典の境界値 |
| `packages/core/test/trend-metrics-contract.test.ts` | 指標の登録表・総収支との一致・3 指標×3 範囲×2 比較対象の恒等式 |
| `packages/api/test/trends-screen.integration.test.ts` | `GET /api/trends` の契約 (400・既定値・総収支 API との一致) |
| `packages/web/src/pages/analysis/trends-screen.dom.test.tsx` | 画面の構成・URL の状態・比較できないときの表示 |

既存 Worker 応答に新フィールドが無い場合だけ、旧傾向判定 (MK 検定・Theil-Sen・手を打つ順番) を
rolling deploy の fallback として表示する。新しい比較画面では重複表示しない。旧判定の数値規則は
`packages/core/src/trend.ts` と `packages/core/test/trend-contract.test.ts` が正で、本書では扱わない。

## この画面が答えること

「収支は、いつ・なぜ変わったか」。選んだ期間の収入・支出・純収支の月次推移と、
前期間または前年との差を総合・事業・家計で読み、最も変化が大きい月の増減要因を
カテゴリと取引先まで辿って明細へ移れるようにする。

## 数値の出所

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 数値の出所 | 総収支と同じ `totalCashflowLedger` の行集合。freee 取引と MF 明細を `totalCashflowReport` と同じ判定で消し込み、除外済みは数えない | 事業・家計・総合の月次値は `monthlyTotalCashflow` の同じ月と一致する | `事業・家計・総合の月次値が monthlyTotalCashflow の同じ月と一致する` / api `総合・事業・家計の期間合計と要確認が GET /api/total-cashflow と一致する` |
| 総合 | 事業と家計の和 | どちらかが 0 でも成り立つ | 恒等式テスト `${metric} / ${scope} / ${compare}` |
| 純収支 | 収入 − 支出。支出は正の額で持ち、純収支だけ符号付き | — | `支出は正の額、純収支だけ符号付き` |
| 集計対象 | 数値の出所の行と同じ。MF の計算対象外・振替は数えない | 範囲を事業に絞ると家計の行は出ない | `範囲を事業に絞ると家計の行は出ない` |
| 要確認の明細 | 事業にも家計にも入れず、件数と金額だけを返す。金額は収入と支出を区別しない絶対値の合計 (`sumAbs`) | 0 件なら帯の注記と詳細パネルの行を出さない | `1 件以上なら件数と金額を返し、数値には含めない` / `0 件なら 0` |
| 傾向の判定の基準 | API 互換のため `trendsReport` の MF 集計と `judgementBasis: 'mf_only'` は返すが、新比較画面には描かない | 旧 Worker fallback のときだけ表示する | api `傾向の判定 (rows/pareto/breakdown) は拡張前と同じ MF だけの値で、基準を mf_only と明示する` / web `新しいフィールドが無い応答では、傾向の判定だけを開いて描く` |
| 口座が空の行 | freee 由来で `settleAccount` が空なら `account: null`、表示は「口座情報なし」。口座別の件数と絞込の対象にしない | 件数の合計は口座別件数の和より多くなりうる | `口座が空の freee 行は account null で、口座別の件数に数えない` |
| カテゴリの同一性 | カテゴリ選択は表示名だけでなく `category + side` で識別する | 事業と家計に同名カテゴリがあっても別の行として選べる。旧 URL の `side` 無しは名前だけで互換解決する | `同名カテゴリは side で区別して選択する` / api `category と side の組で選択する` |

旧傾向判定は MF の明細粒度で検定するため、freee と消し込んだ集合へ置き換えず API 互換として残す。
ただし異なる基準を同じ新画面に並べると利用者が誤認するため、描画は旧 Worker fallback に限定する。

## 初回の期間

保存値が無い初回だけ `span=1` (直近1年) を既定にする。比較期間と8列の増減表を最初から使える状態に
するためである。利用者が「全期間」を明示選択した保存値はそのまま復元し、既定値で上書きしない。
壊れた保存値は直近1年へ戻す。Provider 外の安全用 fallback は従来どおり全期間とする。

## 比較期間

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 前期間 (`previous`) | 今回期間の直前で同じ月数 (`previousPeriod`) | 対応月が未取込なら `null`。0 円として増減を出さない | `一部の比較月が無いときは 0 とみなさない` |
| 前年 (`yoy`) | 前年の同じ月範囲 (`previousYearPeriod`) | 対応月が未取込なら `null`。0 円として増減を出さない | 同上 / api `compare=previous と yoy で比較期間の月範囲が決まる` |
| 月の並べ方 | 比較の月は今回の月と同じ位置で並べ、月次差は同じ位置の月との差 | — | `比較の月は同じ位置の月で並び、月次差は同じ位置の月との差` |
| 比較データ無し | 比較期間に行が 1 件も無ければ比較を作らない (`compareUnavailable: 'no_data'`) | 増減額・増減率は null | `比較期間にデータが無ければ比較を作らない (no_data)。増減は null` |
| 全期間 | 比較期間を作らない (`compareUnavailable: 'all_period'`)。KPI の増減は最も変化が大きい月とその前月の差 (`basis: 'peak_month_mom'`)。カテゴリ表の8列骨格は維持して比較4セルを「—」にし、1年選択の案内とパレート非表示理由を出す | 前月が無い (先頭月) ときは null | `全期間では比較を作らず、増減は最も変化が大きい月の前月差` / web `全期間では比較対象を押せず、その旨を出す` |

## 増減の数え方

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 増減額 | 今回合計 − 比較期間合計 | 比較期間が無ければ null | `増減額・増減率・構成比・寄与度の定義` |
| 増減率 | 増減額 ÷ 比較期間合計の絶対値 | 比較期間合計が 0 なら null (表示は「—」) | `比較期間の合計が 0 なら増減率は null` |
| 構成比 | 行の今回合計 ÷ 指標の今回合計 | 指標の今回合計が 0 なら 0 | `増減額・増減率・構成比・寄与度の定義` |
| 寄与度 | 行の増減額 ÷ 指標全体の増減額 | 全体の増減が 0 なら null。行の寄与度の和は 100% | 同上 / 恒等式テスト |
| 良し悪しの向き | 指標定義の `betterWhen` が持つ (支出は `lower`、収入と純収支は `higher`) | 表示は符号 (+/−) と文字 (増/減) を併記し、色だけで伝えない | web `指標の切替は API の metrics から作り、増減は符号と文字を併記する` |

## カテゴリ表の並べ替えとレイアウト

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 8列ソート | カテゴリ、12か月の変化量、今回合計、比較期間、増減額、増減率、構成比、寄与度を昇順→降順→元の順序で切り替える | 比較値が無い行は null とし、安定ソートする。12か月は最初と最後の記録値の差 | web `8列すべてを三状態でソートする` / `aria-sort` |
| 親子行 | 取引先の展開行は親カテゴリとひとまとまりで移動する | ソートで取引先だけを別位置へ移さない | web `展開した取引先行は親カテゴリと一緒に移動する` |
| 表幅 | fixed layout で 8 列を容器内に収め、右端余白を残す | 54rem 以下と 200% zoom はカード化。通常名は1行、最長名も2〜3行まで | 1280 / 1600 / 1908px 実描画の `scrollWidth === clientWidth`、右端 8px、文字行数 |

## 最も変化が大きい月と選択月

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 最も変化が大きい月 | 月次差の絶対値が最大の月 | 同値は新しい月。全月 0 なら最新月 | `月次差の絶対値が最大の月を選び、既定の選択月にする` / `同値は新しい月、全月 0 なら最新月` |
| 選択月 | URL の `month`。省略・形式違反・期間外は最も変化が大きい月 | 400 にしない (古いブックマークで画面が出なくなるのを避ける) | `形式違反と期間外の month は最も変化が大きい月へ倒す` |
| データ 0 件 | KPI は 0、選択月と詳細は無い | 画面は空の案内を出す | `データが無ければ KPI は 0、選択月と詳細は無い` / web `データが 0 件なら空の案内を出す` |
| 期間の月 | 今回期間の月はデータのある月に揃える | — | `期間の月はデータの月に揃う` |

## 増減要因と説明文

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 増減要因 | 選択月のカテゴリ別月次差の絶対値の降順 上位 3 | 差が 0 の行は除く | `上位 3 を差の絶対値の降順に並べ、差 0 は除き、説明文は決まった形` |
| 増減パレート | 棒は増減の符号を保ち、累計線は絶対寄与を分母にする | 減少項目を正の棒へ反転しない | web `パレート棒は負の増減を負のまま渡す` |
| 説明文 | `{カテゴリ}が{取引先}{など}{件数}件で{増減額}{増/減}`。取引先は差の絶対値が最大のもの | 取引先が 1 件なら「など」を付けない。外部送信・AI 生成はしない | 同上 / `取引先が複数なら「など」と件数を付け、減少は「減」` |
| 取引先 | MF 由来は明細の内容 (`MfTx.c`)、freee 由来は `FreeeDeal.partner`。名寄せしない | freee 由来で取引先が空なら `(取引先なし)` (`TREND_PAYEE_UNKNOWN`) | — |
| 取引先の選択 | URL の `payee` は取引先行と完全一致で比べる | 部分一致では選ばない | `payee は完全一致だけを選び、部分一致では選ばない` / api `payee は完全一致だけを選ぶ` |
| 初期アクション | 利用者がカテゴリを選んでいなくても、選択月の最大要因を `recommended` として返す。利用者の明示選択 `focus` とは分離する | 要因が無ければ出さない | core `初期状態でも選択月の最大要因を recommended action として返す` / web `詳細パネルは…初期CTAを出す` |
| 遷移先 | MF/mixed 由来は `/classify?month&cls&category&payee`、freee 由来は `/analysis/total-cashflow?month=YYYY-MM`。href の月と増減額は同じ月粒度に揃える | 選択カテゴリが選択月の driver でなければ期間合計として扱い、month を付けない | web `選択バーの確認ボタンは focus.href へ遷移する` / `classify-trends-filter.dom.test.tsx` / core `初期状態でも…recommended action` |

## スパークライン

| 規則 | 定義 | 境界 | 固定するテスト |
|---|---|---|---|
| 月数 | 今回期間の末月から遡る 12 枠 | 期間が 12 か月未満なら期間外の枠は空。`null` の空白を線で跨がない | core `今回期間の末月から遡る 12 枠。12 か月未満の期間では期間外が空` / web `Spark は null の空白を線で跨がない` |

## URL の状態

| 引数 | 値 | 既定 | 誤りのとき |
|---|---|---|---|
| `scope` | `total` / `business` / `household` (旧名 `all` / `biz` / `personal` も受ける) | `total` | 既定値へ倒し、URL も書き換える |
| `metric` | 登録済みの指標 id | `expense` | API は 400 `invalid_metric`、画面は URL から外して取り直す |
| `compare` | `previous` / `yoy` | `previous` | 既定値へ倒す |
| `month` | `YYYY-MM` | 最も変化が大きい月 | 既定値へ倒す |
| `category` / `side` / `payee` | カテゴリ名 / `business`・`household` / 取引先 (完全一致) | 選択なし | 該当が無ければ選択を外す。旧 URL の `side` 省略は許容する |

固定するテスト: web `形式違反の値は既定値として読み、URL も書き換える`、`未登録の metric は URL から外して取り直す`、
api `未登録の metric は 400 invalid_metric、壊れた month・未知の scope/compare は既定値で 200`。

## 指標の足し方

指標は `METRIC_DEFINITIONS` の登録表で引く。画面と API に指標 id の分岐は無い。

1. `packages/core/src/trend-metrics.ts` の `METRIC_DEFINITIONS` に 1 件足す。
   `id`・`label`・`betterWhen` (`higher` / `lower`)・`visualRole`・`controlOrder`・`showInOverview`・
   `valueOf` (1 行がこの指標に足す値)・`breakdownAxis` を書く。
2. `valueOf` は `TrendSourceRow` (総収支と同じ判定を通った 1 行) だけを見る。Dataset を読み直さない。
   別の集合から数えると総収支との一致が崩れる。
3. `packages/core/test/trend-metrics-contract.test.ts` の恒等式テストに id を足す。
   `テスト用の指標を 1 件足すと、分岐を書かずに系列と一覧へ現れる` が型の確認になる。
4. 本書の「良し悪しの向き」に新しい指標の向きを追記する。
5. API (`GET /api/trends` の `metrics`) と画面の指標の切替は、登録表から自動で現れる。
   `showInOverview=false` でも選択中の指標は主図へ必ず出る。画面側に id や日本語 label の分岐を
   書き足す必要は無い。書き足したら設計違反。

## 変えないこと

- D1 のスキーマ。migration は足さない (最新は `0042` のまま)。
- 消し込み・除外・要確認の規則。`total-cashflow.ts` の判定をそのまま使う。
- 既存の `rows` / `pareto` / `breakdown` の値と、応答の `scope` フィールドの旧名。
