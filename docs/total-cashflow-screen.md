# 総収支画面の規則

`/analysis/total-cashflow` が使う判定規則。数値の正本は `packages/core/src/total-cashflow.ts` で、
本書はそこから読める形へ落としたもの。**数値を変えるときは core と本書を同時に直す。**

規則を変えると落ちるテストは `packages/core/test/total-cashflow-screen-rules.test.ts` と
`packages/api/test/total-cashflow-verdict.integration.test.ts` にある。

## この画面が答えること

MF (マネーフォワード) と freee の両方に同じ支出が載っていると、総額が二重に膨らむ。
この画面は「どれが二重なのか」を利用者が 1 件ずつ決められるようにし、
決めた結果を総額へ反映する。

消し込みの正本は freee 側。MF 側の公私仕分けは触らない。

## BR-001 一致度

「この 2 件は同じ取引らしいか」を **0〜100 の整数**で表す。保存せず、毎回計算する。

保存しないのは、口座名の正規化規則を変えたときに古い点だけが残り、
画面の数字と規則が食い違うため。

| 観点 | 配点 | 定数 |
|---|---|---|
| 金額 | 40 | `MATCH_SCORE_AMOUNT` |
| 発生日の差 0 / 1 / 2 / 3 日 | 30 / 20 / 10 / 5 | `MATCH_SCORE_DATE` |
| 口座 一致 / 情報なし / 食い違い | 15 / 8 / 0 | `MATCH_SCORE_ACCOUNT` |
| 摘要 一致 / 一方が他方を含む / それ以外 | 15 / 8 / 0 | `MATCH_SCORE_TEXT` |

金額が常に満点なのは、同額・同じ向きが候補に上がる条件そのものだから。
配っているのではなく「候補である」ことの重みを 40 として明示している。

### 空文字を「部分一致」と読み替えない

摘要と口座は、片方が空なら**一致でも部分一致でもなく「情報なし」**として扱う。
空文字は何にでも含まれるため、素朴に `includes` で判定すると
情報が無い組ほど点が上がってしまう。

### 自動で寄った組の下限

同額・同じ向き・発生日一致で自動的に寄った組は、最小でも
`40 + 30 + 8 + 0 = 78` 点になる。仕様が「78..100 をそのまま表示」と言うのはこの下限のこと。

## BR-002 判定作業の 3 区分

| 区分 | 中身 |
|---|---|
| 重複候補 | 相手が 1 件に絞れていて、日付のずれだけが残っている組 |
| 要確認 | 相手が複数あるか、相手が見つからない明細 |
| freee 除外 | 二重登録として総額から外した freee の取引 |

区分は排他。1 件の明細が 2 つの区分に同時に現れることはない。

## BR-003 自動一致の候補

候補に入る条件:

| 条件 | 値 | 定数 |
|---|---|---|
| 発生日の差 | 3 日以内 | `REVIEW_NEAR_DAYS = 3` |
| 表示する件数 | 上位 3 件まで | `REVIEW_MAX_CANDIDATES = 3` |

並びは **一致度の降順 → 発生日 → id**。
一致度が高い組ほど機械的に片付くため、上から順に押していける。
id を最後に入れているのは、同点のときの並びを実行ごとに変えないため。

> この並び順は仕様が決めていない。実装側で決めた設計判断であり、変更してよい。

## BR-004 セグメント

総合 / 事業 / 家計 の 3 つ。**総合 = 事業 + 家計** が期間合計と月次系列の両方で成り立つ。

除外の理由区分 (`reason_code`) は次の 5 語だけ (`EXCLUSION_REASON_CODES`)。

| 語 | 意味 |
|---|---|
| `transfer` | 口座間の振替 |
| `internal` | 事業と家計のあいだの内部移動 |
| `book_only` | 帳簿上だけの計上 |
| `duplicate` | MF 側と同じ取引の二重登録 |
| `other` | 上のどれでもない |

メモ (`memo`) は 0〜200 字 (`EXCLUSION_MEMO_MAX`)。理由の自由文 (`reason`) は 1〜200 字で必須。

移行 0042 より前に保存された除外は、`reason_code` が一律 `other`、`memo` が `NULL` になる。
**理由文から区分を推測して振り分けていない。**「振替」と書いてあっても、
それが `transfer` と同じ意味で書かれた保証がないため。
画面は `memo ?? reason` を出すので、既存行は今までどおり理由文が読める。

## BR-005 除外後の数え方

除外した freee 取引は総額から引く。要確認の数え方はここで分岐する。

| 状況 | 扱い |
|---|---|
| 候補がちょうど 1 件で、それが除外済み | **要確認から出す** |
| 候補が 2 件以上で、その一部または全部が除外済み | 一覧に残す (候補欄が空になるだけ) |

候補 1 件のときに出すのは、相手が総額から消えた以上、
この明細は「二重計上かもしれない」ではなく普通の支出であり、公私仕分けで数えるのが正しいため。
除外を戻せば自動で要確認へ戻る。

候補が 2 件以上あった組を残すのは、**どれと同じだったかを機械が名指しできない**ため。
ここで消すと、明細ごと一覧から見えなくなる。

判定は**除外前の候補数**で行う。除外後の数で決めると、
候補 2 件の両方を除外したときに明細が一覧から消える。

## BR-006 前年同期比

選択中の期間と、その 1 年前の同じ期間を比べる (`previousYearPeriod()`)。

| 状況 | 表示 |
|---|---|
| 前年同期にデータがある | 差額と率 |
| 前年同期が 0 | 差額のみ (率は出さない) |
| 前年同期のデータが無い | 『比較データなし』 |

前年同期が 0 のときに率を出さないのは、0 除算の結果を `Infinity` や `∞%` として
画面に出さないため。

符号 (`+` / `-`) と矢印 (`↑` / `↓`) を必ず添える。色だけに頼らない (WCAG 2.2 AA)。

> 表記は「前年同期比」に統一する。仕様に「前期比」との混在があったが、
> 比べているのは 1 年前の同じ期間なので後者は誤り。

## BR-007 判定進捗

表示中の区分について「N 件中 M 件の判定が完了しました」を出す。
N と M はどちらも core が返す件数から導き、画面側で数え直さない。

区分を切り替えると N も M も変わる。

## BR-008 取消

『元に戻す』は、**その画面を開いてから行った未取消の操作**を新しい順に 1 つずつ戻す。
再読込や画面の移動の後は導線を出さない。

失敗の理由は 4 つに分かれる。ひとまとめの 409 にしていないのは、
「もう一度押せばよいのか、読み直すべきか」を画面が説明できなくなるため。

| code | HTTP | 文言 | 画面の振る舞い |
|---|---|---|---|
| `not_found` | 404 | この操作は見つかりませんでした | 選択を保つ |
| `already_undone` | 409 | この操作はすでに元に戻されています | 選択を保つ |
| `not_undoable` | 409 | 取り消しそのものは元に戻せません | 選択を保つ |
| `stale_operation` | 409 | 別の更新と重なりました。もう一度お試しください | **再読込を促す** |

取消も履歴に 1 行として残す。履歴から消す作りだと「なぜ値が戻ったか」が後から読めない。
その 1 行 (`kind = 'undo'`) 自体は取り消せない (`not_undoable`)。

「直前の操作」は `created_at DESC, id DESC` で決める。
同じミリ秒に 2 行入ったときも順序が一意になるよう、id を第二鍵に置いている。

詳しい復旧手順は `docs/runbooks/total-cashflow-undo-conflict.md`。

## BR-009 消し込みの不変条件

除外は freee 側の総額からだけ引く。MF 側の公私仕分け (`resolveTx`) には触れない。
判定 (`same` / `different`) を記録しても総額は変わらない。

検算式:

```
coverage.matched + coverage.freeeOnly + coverage.excluded === coverage.freeeTotal
```

freee の全件が必ず「一致 / 除外 / どちらにも入らない残余」のどれか 1 つに入る。
この式は除外の前後どちらでも成り立つ。

## データの保護

`duplicate_verdicts` / `freee_deal_exclusions` / `total_cashflow_operations` の 3 表は、
**バックアップと復元の対象に入っている**。

| バックアップ | 復元後 |
|---|---|
| 3 表の key を持たない (移行 0042 以前に取ったもの) | 既存の判断がそのまま残る |
| 3 表の key を持つ | その時点の判断へ戻る |

key の有無で分けているのは、旧バックアップの復元が
「判断を全部消す操作」になるのを避けるため。

## 入力の上限

| 項目 | 上限 |
|---|---|
| 一括の除外 / 復元 | 200 件 |
| 一括の判定 | 200 件 |
| 理由の自由文 | 200 字 (必須) |
| メモ | 200 字 (任意) |

上限を超えた要求は**全体を 400 で拒否する**。一部だけ通して残りを黙って捨てない。
