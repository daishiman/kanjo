# 使い方画面の30視点レビュー（2026-09-24）

対象は今回の未コミットの `feat-guide-screen` 実装。最初に従来の対策を判断根拠から外し、画面・core・API・既存画面・仕様を読み直した。ファイルや成果物は削除していない。以下は各思考法から得た具体的な判断であり、同じ問題を異なる視点で確認した行は独立した実装タスクに増やしていない。

| # | 思考法 | 観察と採用した判断 |
|---:|---|---|
| 1 | 批判的思考 | FAQ の「同一日付・類似の取引先」を疑い、照合の実規則と食い違うことを確認した。`guide-screen.ts` の説明を候補条件へ合わせた。 |
| 2 | 演繹思考 | 「前後移動の結果は全期間内」という規則から `shiftedPeriod` を検査し、部分的な範囲外移動を拒否するよう直した。 |
| 3 | 帰納的思考 | 右カラムのラベルと期間移動 UI が複数箇所で繰り返されていた。core のラベルと Web の共通部品に集約した。 |
| 4 | アブダクション | 期間切替直後の旧数値は `keepPreviousData` による応答の保持で説明できる。placeholder を読込状態として扱った。 |
| 5 | 垂直思考 | 検索後の無関係な本文をたどると、検索結果と URL の `topic` を合成する規則の欠落に行き着いた。表示用 topic を一箇所で決める。 |
| 6 | 要素分解 | ページの入力を静的説明、API 数値、URL、共通期間に分解した。期間変更中は数値だけを待たせ、静的説明は残す。 |
| 7 | MECE | 検索を「トピック一致」「疑問だけ一致」「一致なし」に分け、いずれでも目次・本文・下部バーが矛盾しない状態を定めた。 |
| 8 | 2軸思考 | 静的/動的と期間依存/非依存で整理した。総収支と用語の現在値は期間依存、説明文と月次レビューの定義は期間から独立する。 |
| 9 | プロセス思考 | 期間選択→問い合わせ→結果表示の途中を検証し、未確定の値を完成値として見せないようにした。 |
| 10 | メタ思考 | 検索0件でも旧本文を残すテストは、探索の成功を保証しない。テストの期待を利用者の操作結果に合わせた。 |
| 11 | 抽象化思考 | 上段4ステップは行動案内、本文の4段は月次クローズの実進捗。見た目が似ても意味を混ぜない。 |
| 12 | ダブル・ループ思考 | 「検索は目次だけ絞ればよい」という前提を改め、検索結果から説明と元画面へ戻る導線を一体で定義した。 |
| 13 | ブレインストーミング | 自動移動、件数表示、FAQへのスクロール、選択項目の維持を比較し、最初の一致へ移る最小の規則を採用した。 |
| 14 | 水平思考 | 読む資料としてだけでなく、元画面への案内として見直した。下部バーは表示中の説明と同じ行き先にする。 |
| 15 | 逆説思考 | 進捗表示を増やすと誤認が増える場合がある。「計画」を review 完了で塗らず、進捗の4段目を「月次レビュー」とした。 |
| 16 | 類推思考 | 通常のタブと同じく、選択タブとパネルを対応させる。検索で選択タブが消えたまま本文だけ残る状態を解消した。 |
| 17 | if思考 | もし「1年」を選んで用語を開いたら、期間なしの `/summary` と `/diagnosis` は総収支と食い違う。両方を共通期間で取得する。 |
| 18 | 素人思考 | 「計画」の完了印は予算を作ったと読まれる。利用者に見える進捗名を実際の「月次レビュー」に合わせた。 |
| 19 | システム思考 | core の説明と導出、API の数値、Web の用語辞書という依存の向きを保ち、辞書を core に複製しない。 |
| 20 | 因果関係分析 | 検索が候補だけを変え、本文が URL の古い topic を読むことが不一致の直接原因。選択規則を view-model へ集約した。 |
| 21 | 因果ループ | 新期間を選んだのに旧数値が残ると再操作を誘う。確定まで数値と期間表示を読込状態にして循環を断つ。 |
| 22 | トレードオン思考 | 既存の総収支・進捗計算を再利用しながら、ガイドには不要なサブスク候補計算だけをレビューキュー経路へ移した。 |
| 23 | プラスサム思考 | 期間移動を共通部品にし、ガイドと決算書の修正箇所を一つにした。両画面の行動は維持する。 |
| 24 | 価値提案思考 | 画面の価値は「数字を読み、直す画面へ戻る」こと。検索結果・本文・下部バーの一致を優先した。 |
| 25 | 戦略的思考 | 優先順位は誤値/誤説明→状態の不一致→重複整理→見た目の検証。共通シェルの全面変更は今回の範囲に含めない。 |
| 26 | why思考 | なぜ本文が違うか→旧 topic を使う→検索は候補だけ変える→状態合成がない→テストが不一致を許す、の5段で原因を確認した。 |
| 27 | 改善思考 | 期間の境界、誤説明、検索、用語の期間、事実ラベル、移動 UI の順に、局所的な修正へ分けた。 |
| 28 | 仮説思考 | `q=重複` で一致タブ/本文/リンクが揃い、FAQだけ・0件でも旧本文が出ないなら探索の迷いが減るという仮説を DOM テストで反証可能にした。 |
| 29 | 論点思考 | 重複行数より、選択期間・検索結果・表示本文・元画面リンクが同じ意味を指すかを主要論点とした。 |
| 30 | KJ法 | 発見を「状態同期」「正本と依存」「表示と検証」に束ね、独立した修正を並列化し、最終検証で合流させた。 |
