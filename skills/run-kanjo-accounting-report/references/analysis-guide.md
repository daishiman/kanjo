# データの読み方と分析観点

## 1. 取得JSONのキー

| キー | 意味 |
|---|---|
| `period` | 対象期間。`months` は期間内で取込済みの月、`previous` は前期(前月/前年)、`yearAgo` は前年同期 |
| `months` | 取込済みの全月(昇順)。全期間の傾向はこれを使う |
| `unrecordedExpenseMonths` | 事業経費が**未記帳**の月。この月の経費 0 は「支出なし」ではない。増減の比較対象から外す |
| `biz.revenue` / `biz.expenseTotal` | 月別の事業売上 / 事業経費合計(freee 帳簿) |
| `biz.expenseByAccount` | 勘定科目 → 月別金額 |
| `biz.kpi` | 平均売上・平均経費・直近経費・前月比(`expenseMom`)・前年経費・今年の年換算 など |
| `biz.yearTable` / `biz.yearTotals` | 科目別の前年実績と今年の年換算(`delta` は 1=100% の小数) |
| `biz.pareto` | 経費の大きい順と累積構成比(`cumShare`) |
| `personal.byMonth[月].expense` | 個人支出(MF 明細のうち公私仕分けで「個人」)。キーは大項目(または大項目/中項目) |
| `personal.byMonth[月].income` | 個人収入 |
| `personal.livingCost` | 生活費の大項目別(全期間の合計・月平均・年換算・構成比) |
| `personal.explainability` | 個人支出の説明可能率(未分類・カード引落不明を除いた割合) |
| `bizPersonal[月]` | MF 明細のうち「事業」と仕分けされた分の収入・支出(freee とは別集計) |
| `comparison` | 事業と個人を月別に並べた収支。`biz`/`personal` に合計・月平均・年換算 |
| `byOwner` | 個人分の名義別(`self`=本人 / `spouse`=妻 / `unset`=未設定)。`unmappedInstitutions` は名義未設定の金融機関 |
| `subscriptions.now` | 直近記帳月のサブスク合計・年換算・直近12ヶ月合計・売上比 |
| `subscriptions.vendors` | ベンダー → 月別支払 |
| `subscriptions.vendorTable` | ベンダー別の前年実績・年換算・直近月額・平均月額・支払月数 |
| `subscriptions.alerts` | 重複疑い・急増のアラート |
| `benchmarks` | 経費率・サブスク比率・安全余裕率・貯蓄率・食費比率・通信費比率の現在値と目安 |

金額はすべて円の整数。比率は 1=100% の小数(表示は % に直す)。

## 2. 分析のチェックリスト(節ごと)

### spend(何にいくら)
- 対象期間の事業経費合計・個人支出合計を先に置く(対象期間が複数月なら合計と月平均)。
- 上位科目を構成比つきで並べる。`pareto.cumShare` が 0.8 を超えるまでの科目が「管理の主戦場」。
- 固定費(毎月ほぼ同額)と変動費を分けて言う。月別の並びからブレの大小を読む。

### change(増減と要因)
- 比較対象は `period.previous` と `period.yearAgo`。**どちらかの月が `months` に無ければ「データ不足」**。
- 合計の差額と率 → 差額の大きい科目3〜5個 → その科目の月別推移で「一時的か継続的か」を判断する。
- `unrecordedExpenseMonths` に含まれる月は比較に使わない(理由を明記)。

### reduction(削減余地)
- 候補は「金額が大きい × 固定的 × 代替がある」順に優先度を付ける。`priority` は high/mid/low。
- 各候補に 年換算金額・根拠(どの数字から言えるか)・実行時の注意(事業に必要な支出は削らない)を書く。
- `benchmarks` で目安外の指標があれば、その指標を動かす科目を候補にする。
- 削れないもの(税金・社会保険・家賃など)は候補に入れず、「固定で見直し対象外」と一言添える。

### split(事業/個人・本人/妻)
- `comparison` から事業と個人の収支(合計・月平均)を並べる。個人の赤字を事業収入で埋めていないか。
- `byOwner` から本人/妻の収入・支出。`unset` が大きい、または `unmappedInstitutions` があれば「設定画面で名義を割り当てると精度が上がる」と書く。
- `bizPersonal` が大きい月は、MF 側で事業扱いの支出が freee に未記帳の可能性を指摘する(断定しない)。

### subscriptions(サブスク)
- `subscriptions.now` の合計・年換算・売上比を先に置く。
- `alerts` を必ず反映(重複疑い・急増)。`vendorTable` で支払月数が少ない・直近月額が平均より高いものを候補に。
- 整理候補は「解約 / プラン変更 / 年払い切替 / 継続」の4区分で書き、理由を添える。

## 3. データ不足の書き方

- 何が無いか(例: 2025-08 の個人支出)と、それにより何が言えないか(前年同月比)を1行で。
- 取込で解消するものは「MF/freee の該当月を取り込むと比較できる」と添える。
