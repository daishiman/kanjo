## U1 本質的目的 (essential_purpose)

支出分析のマトリックス画面を、『どの月・どのカテゴリに支出が偏っているか』をヒートマップ 1 枚で特定し、偏っているセルを選んでその正体 (含まれる取引・前月比・前年同月比・データの出典) まで降り、該当明細へ移動して手を打つところまでを 1 画面で完結できる発見の場にする。月次クローズの『確認』段階で、利用者が表示モード (全部 / 構成比 / 前年差)・集計の対象 (総合 / 事業 / 家計)・行の分類 (カテゴリ / 取引先) を切り替えながら偏りを探し、偏りが大きい 3 点の示唆を読み、選択中のセルから明細へ一直線に進める状態にする。

## U2 背景 (background)

現行の /analysis/matrix (packages/web/src/pages/analysis/Matrix.tsx、174 行) は GET /api/matrix が返す core の matrix(data) をそのまま描く読み取り専用の表で、行は事業の勘定科目 + 経費計 + 売上（記帳）に固定され、列は月 + 年計 + 前年比、表示モードは 金額 / 前月比 / 前年同月比 の 3 つ、加えて MatrixMoversChart と色の凡例しかない。セルを選ぶ操作が無く、ヒートマップの濃淡・行列の合計と平均・構成比・家計や取引先の軸・セルに含まれる取引の内訳・データの出典・偏り上位 3 点の示唆・空状態の取込導線が無いため、偏りを見つけたあと『その金額の正体は何か』を追うには明細仕分けや総収支タブを往復する必要がある。design/FINAL-UI は 06 マトリクスを『良好→整理。主役は明確。表示モード、セル詳細、データ不足状態を追加』と監査し (spec/AUDIT.md)、必須機能を『表示モード切替、ヒートマップ、行列合計、セル詳細、データ不足／取込導線』と定めている (spec/FUNCTION-MATRIX.md)。最終採用 UI 画像 design/FINAL-UI/images/06-matrix.png がこのサイクルの正本であり、サイドバー・ヘッダー・フッターは直前サイクル (照合・概況・分析ハブ) で確定した共通シェルをそのまま使う。画像は本サイクルで画素レベルまで解析し、specs/spec-expense-matrix-screen.md に再現仕様 (領域の版面比・完全一致文言・表のフィクスチャ数値・濃淡階級・詳細パネルと偏り 3 点の規則・API 契約・受入 7 項目) として確定した。

## U5 成功基準 (success_criteria)

- S1 (G1): /analysis/matrix で 06-matrix.png の構成要素がすべて描画され、色・余白・部品はトークンと共通 Button / PageShell 経由で、直書き色の lint が 0 件である。
- S2 (G2): 任意のセルを選ぶと詳細パネルと下部バーが同じ数値 (金額・前月比・前年同月比) を示し、含まれる取引の合計がセル金額と一致し、明細を開くが対象の月とカテゴリで絞った明細へ遷移する。
- S3 (G3): 偏りが大きい 3 点の選定規則が docs に明記され、境界値テストで固定され、表示中のスコープ・軸・期間と同じ条件で算出される。
- S4 (G4): 総合 / 事業 / 家計、カテゴリ / 取引先、全部 / 構成比 / 前年差 のどの組合せでも、合計・平均・構成比が表の値と一致し、matrix CSV および総収支・推移の同一期間の金額と一致する。
- S5 (G5): サイドバー・ヘッダー・フッターの実装差分が表記統一のみで、既存の分析タブ (照合・総収支・推移・診断) のテストが緑である。

## U6 ステークホルダー (stakeholders)

- SH1 利用者 (単独の個人事業主): 月次クローズの確認段階で、どの月・どのカテゴリに支出が偏っているかを 1 枚で見つけ、偏っているセルの中身 (どの取引がいくら) を確かめ、そのまま明細へ移動して手を打ちたい。事業だけ・家計だけ・総合を切り替えて見たい。
- SH2 保守者 (同一人物、および Claude Code などのコーディングエージェント): マトリックスの集計規則 (スコープ・軸・モード・濃淡階級・偏り上位 3 点) が core の純関数 1 か所と docs・テストで固定され、推移・総収支・分析ハブと二重実装にならないこと。

## U7 スコープ (scope)

- **対象 (in)**: マトリックス画面 (06-matrix.png の全構成要素と読込 / 空 / 失敗の各状態) の作り直し, 選択中のセルの詳細パネル (含まれる取引・データの出典・明細を開く) と下部の選択中バー, 偏りが大きい 3 点の算出と表示, core のマトリックス集計純関数 (月×カテゴリ / 取引先、総合 / 事業 / 家計、金額 / 構成比 / 前年差、行列の合計と平均、濃淡階級), GET /api/matrix のセル指向拡張と、セル内訳 (取引一覧・出典) を返す API, サイドバーのマトリックス表記統一と、マトリックスから明細への遷移パラメータ, 集計規則と偏り 3 点の選定規則の docs 記載とテスト
- **対象外 (out)**: サイドバー・ヘッダー・フッター・コマンドパレット・月次クローズ進捗の構造変更 (表記統一を除き既存のまま), 照合・総収支・推移・診断・分析ハブの画面作り直し (数値の整合確認のみ), 新しい取込経路やカテゴリ体系の変更、明細仕分けの機能追加, web 以外のプラットフォーム (mobile / tablet / desktop) 向けの専用実装, AI による要因分析の生成 (偏りの示唆は決定論的な規則で出す)

## U8 制約 (constraints)

- C1 技術: pnpm monorepo (core は依存ゼロの純関数、api は Hono の Cloudflare Worker と D1/Drizzle、web は React 18 + react-router-dom 7 + TanStack Query 5)。集計は core に置き api/web へ重複実装しない。
- C2 デザイン: docs/design-system.md に従い、色は design-tokens.ts 由来のトークンだけ、ボタンは共通 Button (遷移は Link className=btn)、本文は PageShell。ヒートマップの濃淡もトークンの階級で表し、色だけに頼らず数値と凡例を必ず添える。WCAG 2.2 AA を維持する。
- C3 既存方針: 未記帳月は年計・比率から除外し『未記帳』と表示する現行規約、増=赤 / 減=緑 の凡例、usePeriod による期間選択と CSV への期間引き渡しを引き継ぐ。
- C4 対象プラットフォーム: web のみ (既存サイクルの決定を踏襲)。狭幅は既存のレスポンシブ規約 (アイコンレール・縦積み) の中で扱う。
- C5 データ: 取込済みの freee / MoneyForward 由来データと既存 D1 スキーマを使う。セル内訳の取引は既存の明細から引き、新しい保存を必要としない。
- C6 再現の正本: specs/spec-expense-matrix-screen.md (design/FINAL-UI/images/06-matrix.png の画素解析から起こした再現仕様) を画面・集計・API の正本とし、文言・列構成・数値フィクスチャ・濃淡階級・偏り 3 点の規則をここに合わせる。

### 承認: `appr-foundation-expense-matrix-001`

支出マトリックス画面サイクルの上位概念 U1-U9 を利用者が承認 (2026-09-16)。画像 design/FINAL-UI/images/06-matrix.png を正本とし、再現仕様は specs/spec-expense-matrix-screen.md。濃淡=表全体共通7階級 / 示唆=決定論テンプレート / 期間外参照=あり / 取引先軸=上位20+その他 の 4 決定を同時に承認。

#### この承認を名指ししている質疑: `qa-matrix-uiux-web-001`

**問**

web のマトリックス画面 (/analysis/matrix) の UI-UX 要件は何か。画面の構成要素・文言・切替・ヒートマップの読ませ方・セル選択・詳細パネル・偏り3点・空状態・下部バー・アクセシビリティを、design/FINAL-UI/images/06-matrix.png のとおりに確定する。

**答**

上から順に (1) 問いの見出し『どの月・カテゴリに支出が偏っていますか？』と補足『支出の月別 × カテゴリ別の分布を確認し、特定の時期・カテゴリに偏りがないかを把握しましょう。』、右上に『データの最終更新 <日時>』と再取得ボタン。(2) 3 群のセグメント切替 — 表示モード (全部 / 構成比 / 前年差)、集計の対象 (総合 / 事業 / 家計)、行の分類 (カテゴリ / 取引先)。選択は teal 塗り + 白文字で、URL クエリ (mode / scope / axis) に保持する。(3) マトリクスカード: 見出し『月別×カテゴリ別 支出マトリクス』、右に『単位：円』と濃淡凡例 (少ない→多い の 7 階級)。表は行ヘッダ (カテゴリ) を左に固定し月列だけ横スクロール、右端に合計列と平均列、下端に合計行と平均行を置き、平均行の合計・平均は '-'。カテゴリの並びは固定順で『その他』を末尾に置く。(4) セルはクリックと キーボード (Tab / 矢印 + Enter) で選択でき、選択中は濃紺 2px の枠で示し、選択状態も URL に保持する。(5) 選択中だけ『選択中のセルの詳細』カードを表の直下に出す — 見出し『<行の名前> × YYYY年MM月』+ 位置づけバッジ (その月の軸内で最大 / その行の期間内で最大 / なし)、支出金額・前月比・前年同月比の 3 メトリクス (増=赤↑ / 減=緑↓、比較できないときは '—' と『比較できる月がありません』)、『このセルに含まれる取引 (N件)』の表 (日付 / 取引先 / 内容 / 金額 / 区分)、右カラムに『データの出典』(決済手段・更新日時・『明細を開く →』)。× で選択解除。(6) 『偏りが大きい3点』カード (順位の丸バッジ 1=赤 2=橙 3=青、対象 / 金額 / 前月比 / 前年同月比 / 要因の示唆)。(7) データ 0 件では点線枠の空状態カード『表示するデータがありません』『支出データを取り込むと、マトリクスを表示できます。』と『データ取込へ』。(8) セル選択中は画面下に固定バーを出し、『選択中: <セル名>』『金額』『前月比』『前年同月比』と主ボタン『該当明細を確認 →』を詳細カードと同じ値で出す。読込は PageState loading、失敗は PageState error、セル内訳だけの失敗は詳細カード内でインライン表示にする。アクセシビリティは WCAG 2.2 AA を維持し、濃淡は必ず数値と凡例を伴わせて色だけに頼らせない。狭幅ではセグメント群を縦積みにする。寸法・文言・フィクスチャ数値の正本は specs/spec-expense-matrix-screen.md。

#### この承認を名指ししている質疑: `qa-matrix-backend-web-001`

**問**
