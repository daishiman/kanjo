## U1 本質的目的 (essential_purpose)

使い方画面を、『この数字を、どう読み・どこへ戻ればよいですか？』という問いに 1 画面で答え切る場にする。月次の流れ (取込む→整える→確認→計画) の中で今見ている数字が何を含み何を除くか・どの期間の・どこから来た値かを、選択中の期間の実データで示し、つまずいたら該当の元画面へ 1 クリックで戻れるようにする。数字の読み違い (振替の二重計上・家計と事業の混同・信頼度や防衛ラインの誤解) による判断ミスと、迷って作業が止まることを無くす。

## U2 背景 (background)

現行の /guide (packages/web/src/pages/Guide.tsx、185 行) は用語集・略語・ベンチマーク・データ充足度を並べた指標の辞書で、期間と連動せず (/api/summary と /api/diagnosis を期間なしで読む)、月次の流れ・元画面への戻り道・よくある疑問・このページの数値の定義が無い。現在値の合成も web 側 (guide-sections.ts) にあり core に無い。画像の説明と実装が食い違う点が 4 つあり、1 点ずつ利用者が決めた: 信頼度は画像どおり 3 段階＋% にする (qa-guide-decision-008)、防衛ラインは算出 (直近 3 か月平均) を変えずガイドの説明を実装に合わせる (qa-guide-decision-009)、共通シェルのヘッダは『防衛ライン』のまま (qa-guide-decision-010)、フッタ 1 文目は画像の文言にする (qa-guide-decision-011)。design/FINAL-UI/images/19-guide.png がこれらを 1 画面に並べた完成形を示したため、画面を作り直す。

## U5 成功基準 (success_criteria)

- S1 (G1): /guide で 19-guide.png の構成要素がすべて描画され、総収支の 3 枚が選択期間の実データ (振替除外) と一致し、色・余白・部品はトークンと共通部品経由で直書き色の lint が 0 件である。
- S2 (G2): 信頼度 49/50/79/80 の境界が 低/中/中/高 になり、全画面で段階＋% が出る。防衛ラインの値は変わらず (直近 3 か月平均)、使い方画面と用語集の説明がその算出と一致する。自動判定 (要確認の閾値 80) の結果は変わらない。
- S3 (G3): ガイドの節・よくある疑問・期間の表・このページの数値が core の guide-screen だけで導かれ、API と web はその結果を写すだけである。
- S4 (G4): ヘッダは『防衛ライン』のまま、フッタが『取込データは外部送信しません』になり、AI 実行時に集計データを渡す補足がフッタ・プライバシー欄・使い方画面の 3 か所で読める。他の利用者のデータで /api/guide が数値を返さない。

## U6 ステークホルダー (stakeholders)

- SH1 利用者 (個人事業主とその家族の家計を 1 人で管理する): 月次クローズの途中で数字の意味に迷ったとき、その数字が何を含み何を除き、どの期間のどこから来た値かを確かめ、直すべき元画面へすぐ戻りたい。
- SH2 家族 (配偶者・家族の名義で支出する): 家計と事業の範囲の分け方が正しく説明され、家計の数字が事業と二重に数えられていないことを利用者が確かめられる。

## U8 制約 (constraints)

- C1 技術: pnpm monorepo (core は依存ゼロの純関数、api は Hono の Cloudflare Worker と D1/Drizzle、web は React 18 + react-router-dom 7 + TanStack Query 5)。判定と導出は core に置き api/web は写すだけにする。
- C2 データ: 本サイクルは DB の列を足さない。防衛ラインの算出も、既存の集計結果 (総収支・振替除外) も変えない。
- C3 表示: 全用語がどこかの画面で使われる lint (check-glossary)、ルート数固定テスト、PageHeader 規約、共通部品規約、直書き色禁止を守る。
- C4 品質: 初期 JS 予算 (110KiB)・verify:full・skills:test を緑のまま保つ。税務上の正本は freee であり、本画面は税務判断をしない。
