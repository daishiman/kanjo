## U1 本質的目的 (essential_purpose)

決算書画面を、『損益・資金・残高は、整合していますか？』という問いに 1 画面で答え、整合していない箇所 (集計できない資金、未入力の負債) をその場で決着 (原因の把握と取引データへの移動、負債残高の入力と保存) まで進められる場にする。利用者が損益計算書・キャッシュフロー計算書・貸借対照表を前期比・出典・対象期間つきで読み、数字の根拠 (計算式・内訳の勘定科目・月別の推移・データの出典) を辿り、『0円』と『未入力』を取り違えずに負債残高を入れられる状態にする。

## U2 背景 (background)

再設計前の /statements は packages/web/src/pages/Statements.tsx 1 ファイル（657 行）に PL・CF・BS・負債入力と画面側計算を抱え、前期比・出典・段階損益・CF の原因と解決手順・負債の未入力状態を欠いていた。保存も月の manual 負債を全削除してから挿入するため、1 種類だけ保存すると他項目が消える課題があった。現在の packages/web/src/pages/Statements.tsx は packages/web/src/pages/statements/StatementsPage.tsx の 2 行の re-export だけを持ち、KPI・PL・CF・BS・下書き・CSV は pages/statements/* に分割済みで、表示値は core の statementsScreen と GET /api/statements の screen-only 契約を正本とする。design/FINAL-UI/images/11-statements.png と spec/AUDIT.md:17 は再設計の基準と、当初の負債入力・0/不明・BS不足・CF限界の差を示す。

- C3 データ: 取込データと下書きは外部送信しない。区分の対応表はコード内の固定表で持ち、外部 API を呼ばない。
- C4 DB: 破壊的な行書き換え migration をしない。実 migration 0046_liability_status.sql は balance_entries への列追加と liability_audit_log の新設だけにし、既存行は『金額あり』の状態として保つ。
