# archive: 2026-09-02 モバイル可視化 + 改善要望テーマ

## 退避の理由

`system-spec/` はリポジトリに1テーマぶんの正本しか持たない構造のため、利用者承認のうえで本テーマをここへ退避し、
`archive/2026-08-31-import-deletion-override-reapply/` を正本へ復帰した。

復帰の目的は、利用者から再提示された要望

> この取り込みの知っている情報を削除する部分がないです。取り込みを削除する機能を追加してほしいです。
> …似たような情報や同じ情報が更新されたら、それを上書き更新する機能も反映されていません。
> …コンフリクトが発生した場合はユーザーに尋ねてこれを整えるフローができるようにしておいてほしい。

に対して、既に確定済みの `feat-import-deletion-override-reapply` テーマを正本として再開し、未決事項 D01〜D04 を
埋めたうえで実装へ進めること。

## 退避の手順（契約順守の記録）

1. 本テーマの確定セル 12 件を `apply-spec-transition.py apply --op '{"action":"reopen",...}'` で理由付き再オープンした。
   確定セルを直接 `未収集` へ書き換えることは契約違反であり、`reopen` だけが確定セルを動かせる唯一の遷移である。
   再オープンの理由は `spec-state.json` の `reopen_log` に 12 件記録済み（退避後の本ディレクトリの `spec-state.json` を参照）。
2. 正本直下のファイル群と `retrieval-evidence/` を本ディレクトリへ退避した。
3. `archive/2026-08-31-import-deletion-override-reapply/` の内容を正本へ復帰した。

## 退避時点の内容

- テーマ: モバイル表示の可視化改善 + 利用者からの改善要望受付
- 要件基盤: U1、目標 G1〜G11
- カバレッジ: 8 カテゴリすべて確定（退避前）→ 退避手順1で再オープン済み
- `dev-graph-import-report.json` は本テーマ固有の C02 取込レポートのため、正本へは戻していない。

## 復帰したい場合

本ディレクトリのファイルを正本へ戻す前に、そのときの正本テーマの確定セルを同じく `reopen` で
理由付き再オープンし、`archive/<日付>-<テーマ名>/` へ退避すること。順序を逆にすると確定内容が失われる。
