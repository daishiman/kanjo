# kanjo 会計分析レポート

アプリが発行した指示文(URL・トークン・期間)を受け取り、**データ取得 → 分析 → 固定構造のレポート送信** を1回で完了する。このスキルは Claude Code と Codex の両方から同じ手順で使う。

## 0. 守ること(最優先)

1. **数字は取得したデータにある値だけ**。金額・科目・ベンダーを推測で作らない。計算した値(差額・比率・年換算)は計算式が言える範囲だけ使う。
2. **無いものは「データ不足」と書く**(例: 前年同月の個人支出が無い)。埋めない・ぼかさない。
3. **5節を毎回すべて出す**(§3)。該当が無い節も「該当なし(理由)」を書いて節は残す。
4. 本文は**プレーンテキスト**(改行と「- 」の箇条書きだけ)。HTML・Markdownの表・見出し記号は使わない。
5. 取得したデータは**リポジトリに保存しない**(コミット禁止)。一時ファイルに置くなら作業終了時に消す。
6. トークンは指示文の中だけで使い、他のファイル・ログ・会話要約に書き写さない。

## 1. 手順

1. 指示文から次を読む: 対象期間 / データ取得URL(GET) / 結果送信URL(POST) / `Authorization: Bearer kjo_…`。
2. データを取得する(認証ヘッダー必須)。

   ```bash
   curl -sS -H "Authorization: Bearer <token>" "<データ取得URL>" -o /tmp/kanjo-ai-data.json
   ```

   - 401 なら期限切れか使用済み。**利用者にアプリで指示文を作り直してもらう**(自分で推測して続けない)。
   - 404 `no_data` なら取込済みデータが無い。その旨を伝えて終了する。
   - ネットワークが使えない環境では、利用者に「AI分析」画面の**「データを表示」**からJSONを貼り付けてもらう。
3. `references/analysis-guide.md` の観点で分析する(データの読み方は同ファイル §1)。
4. `references/report-schema.md` の形でJSONを組み立てる(5節の `id` は固定)。
5. 送信する。

   ```bash
   curl -sS -X POST -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
     --data @/tmp/kanjo-ai-report.json "<結果送信URL>"
   ```

   - `201` → 返ってきた `reportId` を利用者に示して終了(アプリの「AI分析」画面で閲覧できる)。
   - `400 missing_sections` → 不足した節を足して**同じトークンで再送**(未受理なら使用済みにならない)。
   - `400`(検証エラー) → メッセージに従って形を直して再送。
   - `401` → トークン期限切れ/使用済み。利用者に指示文の再発行を依頼する。
   - 送信できない環境では、組み立てたJSONをそのまま提示し、「AI分析」画面の**「結果を貼り付ける」**に貼ってもらう。
6. 一時ファイル(`/tmp/kanjo-ai-*.json`)を削除する。

## 2. 立場と文体

- 税理士・管理会計の実務家として、**事実(数字) → 解釈 → 打ち手** の順で書く。
- 1文は短く。金額は「123,456円」、比率は「12.3%」、増減は「+12,000円(+8.1%)」の形。
- 断定できないことは「〜の可能性(根拠: …)」と書き、根拠の無い推測はしない。
- 利用者は非エンジニア。専門用語は括弧で言い換える(例: 固定費(毎月ほぼ同額で出るもの))。

## 3. 固定の出力構造(毎回この5節・この順)

| id | 節の役割 | 必ず含めるもの |
|---|---|---|
| `spend` | 何にいくらかかっているか | 対象期間の事業経費・個人支出の合計と上位科目(金額・構成比)。`items` に上位科目 |
| `change` | 前年・前月との増減と要因 | 合計と主要科目の差額・率。比較対象が無ければ「データ不足」。未記帳月は増減と混同しない |
| `reduction` | 削減余地と根拠・優先順位 | 候補ごとに 金額(年換算)・根拠・`priority`(high/mid/low)。`items` に候補 |
| `split` | 事業/個人・本人/妻の別 | 事業と個人の収支、名義別の収入・支出。名義未設定の金融機関があれば明記 |
| `subscriptions` | サブスクの整理候補 | 直近月の合計・年換算、重複/急増アラート、見直し候補と理由 |

`summary` は全体の3〜5行の総評。`dataGaps` には判断に使えなかったデータを1件1行で列挙する。
