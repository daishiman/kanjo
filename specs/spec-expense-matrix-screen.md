# 支出マトリックス画面 再現仕様

`design/FINAL-UI/images/06-matrix.png` を画素レベルで解析し、**同じ画面を再現できる**粒度まで
要素・寸法比・文言・数値・状態を確定した仕様。実装 (`packages/web/src/pages/analysis/Matrix.tsx`)
と core / API はこの文書を正本とする。

画像の版面は 1024 × 1568 px 相当 (縮小されたスクリーンショット)。以下の寸法はすべて
**この版面に対する比率**で記述し、実装ではトークン (`design-tokens.ts`) の間隔スケールへ写す。

## 0. 画面骨格

| 領域 | 位置 (版面比) | 扱い |
|---|---|---|
| 左サイドバー | x: 0 → 17% (約 174px)、全高固定 | **既存実装のまま**。表記統一のみ (§7) |
| ヘッダー (パンくず段) | y: 0 → 約 3%、左 17% → 100% | 既存 `PageShell` のヘッダー |
| ヘッダー (期間段) | 直下、約 3% → 5.7% | 既存の期間タブ (`usePeriod`) |
| メイン | 左 17% → 100%、上下にカードを縦積み | **本サイクルの作り直し対象** |
| 下部選択中バー | 画面下に固定、左 17% → 100% | 新規。セル選択時のみ表示 |
| フッター | 最下段 | 既存実装のまま |

背景は淡いブルーグレー、カードは白・角丸・薄い境界線。カード間の縦間隔は版面の約 1.0%。

**色名について**: 本仕様が参照画像を描写して `teal` と書く箇所は、すべて既存トークン

実装で `teal` を探さない。濃淡など不透明度を伴う用途は `chartDecorativeFill(COLORS.accent, opacity)`
を通し、呼び出し側で 16 進 suffix を組み立てない。

## 2. 見出しカード (問いと切替)

### 2.1 文言 (完全一致)

- 見出し (h1): **どの月・カテゴリに支出が偏っていますか？**
- 補足 (1 行): 支出の月別 × カテゴリ別の分布を確認し、特定の時期・カテゴリに偏りがないかを把握しましょう。
- 右上 (小): `データの最終更新` + `2026年9月10日 10:24` + 再取得アイコンボタン (円形矢印、teal)

見出しは版面幅の約 55% を占める大きさ (約 28px 相当)、補足はその 40% 程度の字送り。

### 2.2 切替群

見出しの下に区切り線を挟み、**3 群を横 1 行**に並べる (狭幅では縦積み)。
各群は「ラベル + セグメント」で、セグメントは淡いグレー地のトラックに収まったピル。
選択中は teal 塗り + 白文字、非選択は地色 + 中間グレー文字。

| 群ラベル | 選択肢 (左から) | 既定 | クエリキー |
|---|---|---|---|
| 表示モード | `全部` / `構成比` / `前年差` | 全部 | `mode=all\|share\|yoy` |
| 集計の対象 | `事業` / `家計` | 事業 | `scope=biz\|personal` |
| 行の分類 | `カテゴリ` / `取引先` | カテゴリ | `axis=category\|vendor` |

- **`総合` (`scope=total`) は今サイクルの対象から外す** (利用者決定)。事業と家計を足した表は、
  行の分類が科目のとき同じ科目名が別の意味で混ざる (家計の「通信費」と事業の「通信費」) ため、
  足した数字を見て取れる判断が無い。2 択にすることで、`合計 = biz + personal` という
  維持し続けなければならない不変条件も一緒に消える。
- **`scope` の値は `biz` / `personal`**。`home` ではない。`packages/api/src/routes/analytics.ts:436`
  が既に `raw === 'biz' || raw === 'personal'` で受理しており、`packages/core/src/trend.ts:23-28` の
  `ExpenseScope` / `EXPENSE_SCOPE_LABEL` が語彙の正本である。新しい別名を作らない
  (永続化層の `types.ts:2` `Cls = 'biz'|'per'` は保存形式の語彙なので、これとは別に保つ)。
- 3 群はいずれも **URL クエリに保持**し、リロードで復元する。
- `表示モード` の意味:
  - `全部` = 金額 (万円 1 桁丸め)
  - `構成比` = その月の合計に対する割合 (%、列合計 100%)
  - `前年差` = 前年同月との差額 (±、増=赤 / 減=緑)

## 3. マトリクスカード

### 3.1 カード見出し行

- 左: **月別×カテゴリ別 支出マトリクス**
- 右: `単位：万円` と、濃淡凡例 `少ない ▢▢▢▢▢▢▢ 多い` (7 階級の teal グラデーション見本)
  - 参照画像の表記は `単位：円` だが、同じ画像のセルは万円丸めで描かれている。§3.2 の「単位表記の是正」に従い `単位：万円` を正とする。

### 3.2 表の構造

```
┌ カテゴリ │ 2025/08 … 2026/08 (13列) │ 合計 │ 平均 ┐
│ 仕入高    │ ヒートマップセル ×13      │ 395.3万 │ 30.4万 │
│ …(カテゴリ行)                                        │
│ 合計      │ 各月の合計 ×13            │ 1,139.4万 │ 87.6万 │
│ 平均      │ 各月の平均 ×13            │   -     │   -   │
└──────────────────────────────────────┘
```

月列が 13 なのは期間プリセット `year13` (終了月から遡る 13 か月) をそのまま使うため。
終了月の前年同月が先頭に来るので、終了月は表の中だけで前年同月比を出せる。

- **行ヘッダ列 (カテゴリ)** は左に固定し、月列だけ横スクロールする (既存規約の踏襲)。
- 行ヘッダ列・`合計` 列・`平均` 列・`合計` 行・`平均` 行は淡いグレー地で本文セルと区別する。
- `合計` 行と `合計` 列の交点は総合計 (`1,139.4万`)、`平均` 行の `合計`/`平均` 列は `-`。
- 月見出しは `YYYY/MM` 形式 (例 `2025/08`)。
- 値は万円単位 1 桁丸め + `万` (例 `28.5万`)、合計列は桁区切り (`1,139.4万`)。
- **単位表記の是正**: 参照画像は見出し行に `単位：円` と書きながら、セルは万円丸め (`28.5万`) で描かれており表記が食い違っている。実装では**セルの万円丸め表記を正**とし、見出し行の表記を `単位：万円` へ直す (画像の表記ゆれの是正であり、数値の意味は変えない)。§4 のセル詳細パネルだけは円単位の実額 (`¥240,000`) を出す — 表は俯瞰、詳細は実額という役割分担にする。

### 3.3 ヒートマップの濃淡

- **スケール基準: 表全体で共通** (表示中の全データセルの最小〜最大を 7 階級に等分)。
  - 合計行・平均行・合計列・平均列は**スケール算出から除外**し、地色のままとする。
  - **除外するのは階級を計算する側**であり、描画部品ではない。合計・平均を含めたまま最小〜最大を
    取ると本体セルが最下位階級へ潰れる (総計は個々のセルより一桁大きい) ため、
    階級を計算する関数に渡す時点で本体セルだけの配列にする。描画部品は渡された階級値を
    色に変えるだけで、どの行が合計かを知らない (`dec-matrix-heat-scale`)。
- 階級は `COLOR.accent` の不透明度 7 段 (最も薄い = ほぼ無色、最も濃い = 凡例右端)。
  直書き色を作らず `chartDecorativeFill(COLORS.accent, opacity)` を通す。
- **色だけに頼らせない**: セルには必ず数値を表示し、凡例 (`少ない`→`多い`) を添える。
  `前年差` モードでは既存規約どおり増=赤 / 減=緑の符号付き表示にし、濃淡は絶対値で付ける。
- 未記帳月のセルは `未記帳` ピル (中立色) とし、濃淡・合計・平均・比率から除外する (既存規約)。

#### 正規化方針は 2 つあり、どちらも名前を持つ

濃淡の分母の取り方は画面によって違ってよいが、**名前の無い違いは事故になる**ので両方に名前を与える。
共通部品 `heatIntensities(series, normalize)` の第 2 引数がこの名前を取る。

| 名前 | 分母 | 使う場所 | なぜそれでよいか |
|---|---|---|---|
| `table` | 表示中の全データセルの最小〜最大 (7 階級) | マトリックス画面 (本節) | 月をまたいで「どこが濃いか」を一目で比べたいため。行が違っても同じ濃さなら同じ規模である |
| `row` | その行 (科目) の最大 | AI レポートの図 9 ヒートマップ | 科目ごとに規模が桁で違うので、表全体で割ると小さい科目の行が一様に薄くなり山が見えないため。行内の山を見る図である |

§9.1 の `heatScale` は `table` 側の値である。行ごとの分母は API に載せない (§9.1)。

#### `HeatGrid` の props が守る制約

濃淡が 2 か所で別々に実装されていた原因は「正本が無かったこと」ではなく、**変換層が計算済みの値を
落としたこと**である。同じことが起きない形を型で固定する。

1. **制約 1**: `heatIntensities(series, normalize)` の戻り値は**セルごとの階級値そのもの**
   (`(number | null)[]`、正規化済み 0..1 または 1..bands) を持つ。分母は戻り値に含めてよいが、
   `HeatGrid` は分母を**受け取らない**。
2. **制約 2**: `HeatGrid` の props に `max` / `Math.max` / 生の金額配列だけを渡す経路を作らない。
   描画側が分母を再計算する余地を**型で消す**。塗る値は `intensities` からしか来ない。
3. **制約 3**: 中間の変換層を通す経路 (AI チャートの `ChartSeries`) では、階級値が変換層を
   通過することを型で強制する。通過させられないなら**変換層を挟まない** — すなわち AI 側は
   `heat-model` の入力まで生値を運び、`HeatGrid` の直前で `heatIntensities(sr.data, 'row')` を
   呼ぶ。`ChartSeries` の型 (`{label, data}`) は変えない (API とフロントの契約は動かさない)。
4. **制約 4**: `HeatGrid` の外側レイアウトは `HeatGrid` のクラス名に依存しない。高さ・余白の
   扱いは親が props で受け取る。親が子のクラス名を狙って CSS を書くと、部品の内部名が
   外部契約になり動かせなくなる。
5. **色は props で受け取る**: 現行の AI レポートは `COLORS.biz` (`#087f78`) で塗っており、
   本節が指定する `COLOR.accent` とは別のトークンである。色を部品内に固定すると、
   移設した瞬間に AI レポート側の見た目が変わる。

これらは後から型を絞ることができない (呼び出し側が既に分母を渡していると剥がせない) ため、
`HeatGrid` の props を最初に決める時点で満たす。

### 3.4 セル選択

- 本文セルはクリックおよびキーボード (Tab/矢印 + Enter) で選択できる。
- 選択中のセルは**濃紺 2px の枠 + 角丸**で示す (画像: 広告宣伝費 × 2026/03)。
- 選択は URL に保持する (`cell=<行キー>:<YYYY-MM>`)。
- 選択すると §4 の詳細カードと §6 の下部バーが現れる。解除で両方が消える。

### 3.5 画像の実データ (再現テスト用フィクスチャ)

`表示モード=全部` / `集計の対象=事業` / `行の分類=カテゴリ`。単位: 万円。

(ヘッダの `事業` は表記の修正ではなく整合の修正である。この表の 7 行は仕入高・人件費・外注費など

#### 3.5.1 表の外の前年参照データ (`mode=yoy` 検算用)

`mode=yoy` は §9.3 のとおり**表示期間外でも実データがあれば参照する**ため、窓の外の月が要る。
受入が要求する分だけを定義する (窓外の全月を埋めない)。

| 月 | カテゴリ | 値 | 何のために要るか |
|---|---|---|---|
| 2025/03 | 広告宣伝費 | 6.0 | 受入2 の `2026/03` の前年同月比 (`24.0 - 6.0 = +18.0` / `+300.0%`) |

先頭列 `2025/08` の前年同月 (`2024/08`) は定義しない。`mode=yoy` の当該セルは `—` になる
(§9.3 の「前年同月が無い場合は `—`」がそのまま適用される)。

カテゴリの並びは**合計金額の降順ではなく固定順**
(仕入高 / 人件費 / 家賃・地代 / 広告宣伝費 / 外注費 / 通信費 / その他) で、`その他` を必ず末尾に置く。

## 4. 選択中のセルの詳細カード

セル未選択のときは**カードごと出さない**。選択時のみ、マトリクスカードの直下に出す。

### 4.1 ヘッダー

- 左: 小見出し **選択中のセルの詳細**
- 右: `×` 閉じるボタン (選択を解除する)

### 4.2 見出しとメトリクス

- h2: `広告宣伝費 × 2026年03月` (`<行の名前> × YYYY年MM月`)
- その右にバッジ: `この月のカテゴリ内で最大` (淡い teal 地)
  - バッジは**該当する位置づけがあるときだけ**出す。規則は次の優先順:
    1. その月の同一軸内で最大 → `この月のカテゴリ内で最大` (取引先軸なら `この月の取引先内で最大`)
    2. その行の期間内で最大 → `この期間でこのカテゴリの最大`
    3. どちらでもない → バッジなし
- メトリクスは 3 枠を横並び (枠の間に縦の区切り線):

| 枠 | ラベル | 値 | 画像の実値 |
|---|---|---|---|
| 1 | 支出金額 | 円建て・桁区切り (大きい字) | `¥240,000` |
| 2 | 前月比 | 矢印 + 増減額 + `(増減率)` | `↑ +¥120,000 (+100.0%)` |
| 3 | 前年同月比 | 矢印 + 増減額 + `(増減率)` | `↑ +¥180,000 (+300.0%)` |

- 増=赤 + `↑`、減=緑 + `↓` (既存の色規約)。比較対象が無い場合は `—` と `比較できる月がありません`。
- **比較対象が表示期間の外にあっても、実データがあれば参照する** (画像の前年同月比 +300.0% がこの前提)。

### 4.3 このセルに含まれる取引

- 見出し: `このセルに含まれる取引 (3件)` — 件数を必ず添える。
- 列: `日付` / `取引先` / `内容` / `金額` (右寄せ) / `区分` (グレーのピル)
- 画像の実データ:

| 日付 | 取引先 | 内容 | 金額 | 区分 |
|---|---|---|---|---|
| 2026/03/05 | 株式会社フューチャー広告 | SNS広告出稿（3月分） | ¥120,000 | 広告宣伝費 |
| 2026/03/12 | Google LLC | Google広告（検索） | ¥80,000 | 広告宣伝費 |
| 2026/03/20 | 株式会社メディアプラン | バナー制作費 | ¥40,000 | 広告宣伝費 |

- **取引の金額合計はセルの支出金額と一致する** (120,000 + 80,000 + 40,000 = 240,000)。
- 件数が多い場合は金額降順で上位 10 件を出し、`ほか N 件` と `明細を開く` へ寄せる。

### 4.4 データの出典 (右側の小カラム)

- 見出し `データの出典`
- 決済手段 (カードアイコン + `クレジットカード`)。セル内で複数ある場合は金額降順で列挙する。
- `更新日時` + `2026年9月10日 10:24`
- ボタン `明細を開く →` (外部リンクアイコン付き・枠線ボタン・カラム幅いっぱい)
  - 遷移先は**選択中の年月とカテゴリ (または取引先) で絞った明細仕分け**。

## 5. 偏りが大きい3点カード

- 見出し: **偏りが大きい3点**
- 補足: `月またはカテゴリで特に支出が大きい、もしくは増加した項目です。`
- 列: `順位` / `対象` / `金額` / `前月比` / `前年同月比` / `要因の示唆`
- 順位は丸バッジ (1=赤、2=橙、3=青)。
- **正本は §5.1 の規則であり、下の表ではない** (利用者決定)。下の表は参照画像に描かれていた
  3 行をそのまま写したもので、§3.5 のフィクスチャへ §5.1 を適用すると
  1 位 広告宣伝費 (2026-03) / 2 位 外注費 (2025-12) / 3 位 その他 (2026-03) になる。
  画像は規則の出力ではなく作図時の例示だったということである。実装・テストは規則の出力を期待値にし、
  下の表は「画像に何が描かれていたか」の記録として残す (期待値として写さない)。
- 画像の実データ (規則の出力ではない):

| 順位 | 対象 | 金額 | 前月比 | 前年同月比 | 要因の示唆 |
|---|---|---|---|---|---|
| 1 | 広告宣伝費（2026年03月） | ¥240,000 | +100.0% | +300.0% | 新製品プロモーションに伴い、広告出稿が増加しました。 |
| 2 | 仕入高（2026年03月） | ¥356,000 | +31.4% | +42.1% | 仕入れ量の増加により、支出が増加しました。 |
| 3 | 広告宣伝費（2026年04月） | ¥162,000 | -32.5% | +125.0% | 3月のキャンペーン継続により、高水準で推移しています。 |

### 5.1 選定規則 (core の純関数・決定論)

表示中の期間・スコープ・軸で算出した全セルを対象に、次のスコアの降順で 3 件を選ぶ。

1. 各セルについて 2 つの偏り量を出す:
   - `月内偏り` = (セル金額 − その月の平均) ÷ その月の標準偏差
   - `行内偏り` = (セル金額 − その行の平均) ÷ その行の標準偏差

   **平均・標準偏差は記帳済み月 (`unrecordedExpMonths` に含まれない月) だけで計算する。**
   未記帳月を 0 として混ぜると平均が下がり標準偏差が上がるため、記帳済みの月がどれも
   「平均より上」に見える。未記帳は「使わなかった」ではなく「まだ記録していない」なので、
   0 として数えない (§9.3 の合計・平均・比率・濃淡と同じ扱い)。
2. `偏りスコア` = max(月内偏り, 行内偏り)。標準偏差が 0 の行・月は 0 とする。
3. 前月比が算出できるセルは `増加ボーナス` = max(0, 前月比) を加える。
4. 同点は 金額降順 → 新しい月 → 行の固定順 の順に決める。
5. 未記帳月・合計行・平均行は対象外。候補が 3 件未満ならある分だけ出す (0 件ならカードを出さない)。

- `行内偏り` は `packages/core/src/analysis.ts` の `catProfile()` が既に持っている規則
  (`sd > 0 ? (lastVal - m) / sd : 0`) と逐語的に同一である。同じ式を 2 か所に書かず、
  `zOf(value, series)` / `zScores(series)` として切り出し、`catProfile` も本節も同じ関数を呼ぶ。
- 診断画面が出す `要確認` は、**同じ行内偏りが 2.0 以上**であることを指す
  (`analysis.ts` の `p.z >= 2`)。別の判定基準ではない。

### 5.2 要因の示唆 (決定論テンプレート)

判定した増減パターンに、金額・比率・件数を差し込む。AI 呼び出しはしない。

| パターン | 条件 | 文 |
|---|---|---|
| 急増 | 前月比 ≥ +50% | `前月比 {前月比} と急増しました。{件数}件の取引が寄与しています。` |
| 増加 | +10% ≤ 前月比 < +50% | `前月比 {前月比} で増加しました。` |
| 継続高水準 | 前月比 < +10% かつ 行平均の 1.5 倍以上 | `前月の高水準が継続しています (行平均比 {倍率})。` |
| 減少後も高水準 | 前月比 < 0 かつ 前年同月比 > 0 | `前月からは減りましたが、前年同月比 {前年同月比} と高い水準です。` |
| 前年比のみ増 | 前月比が算出不可かつ 前年同月比 > 0 | `前年同月比 {前年同月比} と増えています。` |
| その他 | 上記以外 | `金額が期間内で特に大きい項目です。` |

- `{件数}` は §9.1 の `movers` 要素が持つ `txCount` を差し込む。**セル内訳 (§9.2) を取りに行かない。**
  カードは 3 件同時に描くので、内訳を引くと表示のたびに 3 往復増える。
  件数という集約値は本体レスポンスに含める (§9.2 が本体へ含めないと書いているのは
  取引明細そのものであって、その件数ではない)。

### 9.1 `GET /api/matrix`

クエリ: 既存の期間パラメータ + `scope=biz|personal` + `axis=category|vendor` + `mode=all|share|yoy`

```jsonc
{
  "months": ["2025-08", "2025-09", "..."],
  "unrecordedExpMonths": ["..."],
  "rows": [
    { "key": "広告宣伝費", "label": "広告宣伝費", "series": [39000, 42000, ...],
      "total": 1145000, "average": 88077 }
  ],
  "columnTotals": [768000, 789000, ...],
  "columnAverages": [109714, 112714, ...],
  "grandTotal": 11394000,
  "grandAverage": 876462,
  "heatScale": { "min": 20000, "max": 356000, "steps": 7 },
  "movers": [ { "rank": 1, "rowKey": "広告宣伝費", "month": "2026-03",
                "amount": 240000, "txCount": 3, "momRate": 1.0, "yoyRate": 3.0,
                "pattern": "surge", "note": "..." } ],
  "updatedAt": "2026-09-10T10:24:00+09:00"
}
```

- `share` / `yoy` モードの値は**サーバで算出せず**、同じ `series` から core の純関数で導く
  (web と CSV が同じ関数を使う)。
- **上の例示値は §3.5 のフィクスチャから計算した実値である** (`grandTotal` = 1,139.4万、
  `grandAverage` = 1,139.4万 ÷ 13、`heatScale` は本体セルの最小 2.0万 〜 最大 35.6万)。
- **`heatScale` は表示中の全データセルの実測 min/max であり、行ごとには持たない。** これは §3.3 の
  `normalize='table'` (表全体で共通の階級) に対応する値である。行ごとの分母 (`normalize='row'`) は
  レスポンスに含めず、描画側が `heatIntensities` で系列から作る。
- `movers[].txCount` はそのセルに属する取引の**件数**であり、§5.2 の急増テンプレの `{件数}` が参照する。
  明細そのものは含めない (§9.2)。
  以前ここにあった `10820000` は参照画像に**記載されていた**総計であり、画像のセル値の和とは
  一致していなかった (§3.5 の四者不一致のうちの 1 つ)。例示であっても、どこにも接地していない
  数値を仕様に置かない — 読み手はそれを期待値として写すため。

### 9.2 セル内訳

`GET /api/matrix/cell?month=2026-03&axis=category&key=広告宣伝費&scope=biz`

```jsonc
{
  "amount": 240000,
  "mom": { "amount": 120000, "rate": 1.0, "comparable": true },
  "yoy": { "amount": 180000, "rate": 3.0, "comparable": true },
  "badge": "month-max",
  "transactions": [ { "date": "2026-03-05", "vendor": "株式会社フューチャー広告",
                      "description": "SNS広告出稿（3月分）", "amount": 120000,
                      "category": "広告宣伝費" } ],
  "truncated": false,
  "sources": [ { "method": "クレジットカード", "amount": 240000 } ],
  "updatedAt": "2026-09-10T10:24:00+09:00",
  "detailHref": "/classify?month=2026-03&category=広告宣伝費"
}
```

- セル内訳は**選択時に取得**し、マトリクス本体のレスポンスへ含めない (初期表示を軽くする)。
- ここで本体へ含めないのは `transactions` / `sources` の**明細配列そのもの**である。件数のような
  集約値は別で、`movers[].txCount` は本体に含める (§9.1)。明細は行数がセルごとに変わるので
  本体へ載せると初期表示が重くなるが、件数は 1 セルにつき 1 つの数値にすぎない。

### 9.3 集計規則

- `scope`: `biz` (事業) と `personal` (家計) の 2 値。足し合わせた `total` は持たない (§2.2)。
  したがって `total = biz + personal` という不変条件も持たない。
- `axis=vendor`: 期間合計の**上位 20 取引先 + `その他`** 1 行 (残りを合算)。
- `mode=share`: その月の合計に対する割合。列合計は 100%。合計列は期間合計に対する割合。
- `mode=yoy`: 前年同月との**差額**。前年同月が無い場合は `—`。表示期間外でも実データがあれば参照する。
- 未記帳月は合計・平均・比率・濃淡から除外する (既存規約)。
- 平均は**未記帳月を除いた月数**で割る。

### 9.4 `GET /api/export/matrix.csv` の列契約

クエリは 9.1 と同じ (`scope` / `axis` / `mode` + 期間)。同じ core 関数の結果を書き出し、
画面と CSV で数値が食い違う経路を作らない。

列は左から:

| # | 列 | 中身 |
|---|---|---|
| 1 | `科目` (`axis=vendor` では `取引先`) | 行キーの表示名。最終行は `合計` |
| 2〜14 | 各月 (`YYYY-MM`) | **13 列固定**。`year13` (終了月から遡る 13 か月) と同じ窓 |
| 15 | `合計` | 13 か月の期間合計 (未記帳月を足さない) |
| 16 | `平均` | 未記帳月を除いた月数で割った平均 |
| 17 | `前年比(年換算)` | 既存列。`-100.0%` の形で 1 桁 |

- 月列を 13 に固定するのは画面の表と同じ窓にするため。現行の「年計列を年数ぶん可変で足す」
  形は、13 か月窓が 2 年にまたがると年の途中で切れた合計を出すので採らない。
  年をまたぐ比較は 17 列目の `前年比(年換算)` が担う。
- 月列の窓は §3.5 の表と同一。CSV だけ別の窓を切らない。
- 未記帳月のセルは空文字にする (`0` と書かない。0 は「使わなかった」で意味が違う)。
- `mode` は値の意味だけを変え、列の構成は変えない (`share` は `%`、`yoy` は差額)。
- セルの先頭が `=` `+` `-` `@` のいずれかになる場合は先頭に `'` を付けてから引用符で囲む
  (表計算ソフトが数式として解釈するのを防ぐ)。金額の負号もこの対象。
- Excel 互換のため BOM 付き UTF-8 を維持する。

## 10. 受入 (画像再現テスト)

1. §3.5 のフィクスチャを流し込むと、表の全セル・合計行・合計列・平均行・平均列が表と一致する。
2. 広告宣伝費 × 2026/03 を選ぶと、詳細カードが `¥240,000` / `↑ +¥120,000 (+100.0%)` /
   `↑ +¥180,000 (+300.0%)` / 取引 3 件 / `クレジットカード` を出す。
3. 偏りが大きい3点が **§5.1 の規則を §3.5 のフィクスチャへ適用した出力**を出す。
   §5 の表は画像の記録であって期待値ではない (利用者決定「規則を正本にし表を差し替え」)。
   実計算値 (2026-09-17 に `matrixSkewTop` で実行):

   | 順位 | 対象 | 金額 | 前月比 | 前年同月比 |
   |---|---|---|---|---|
   | 1 | 広告宣伝費 (2026年3月) | 24.0万 | +100.0% | — |
   | 2 | 外注費 (2025年12月) | 11.5万 | +26.4% | — |
   | 3 | その他 (2026年3月) | 8.5万 | +19.7% | — |

   前年同月比が 3 行とも `—` なのは、窓 (2025/08〜2026/08) の中に前年同月を持つ月が
   2026/08 しかなく、その月が上位 3 件に入らないためである。§3.5.1 の窓外参照 (2025/03 広告宣伝費)
   は受入2 の詳細カード用であって、この表の算出には使われない (§9.1 の `movers` は窓内で完結する)。
4. 濃淡は表全体共通スケールの 7 階級で、家賃・地代 (12.0万) より仕入高 (26.4〜35.6万) が濃い。
5. 3 つの切替と期間タブとセル選択が URL に載り、リロードで復元する。
6. データ 0 件で空状態カードが出て `データ取込へ` が `/import` を指す。
7. 直書き色 0 件、サイドバー・ヘッダー・フッターの差分は §8 の表記統一のみ。
