# 目的

年に一度の確定申告の準備を、毎年ゼロから作り直さずに済む状態にする。
解くのは3つ。

1. **対象年が曖昧なまま申告額が出る** — 分析用の「全期間」「直近1年」「任意期間」で見た金額が、
   そのまま申告用の書き出しへ流れてしまうと、誰も気づかないまま別の年の数字を転記する。
2. **科目と家事按分を毎年思い出せない** — 「この科目は決算書のどこへ入れたか」「按分は何割で、
   なぜそうしたか」は昨年の自分にしか分からない。記録が無ければ毎年ゼロからやり直しになる。
3. **証憑がどれだけ足りないか分からない** — 明細を1件ずつ開いて確かめる方式は、件数が増えた
   時点で誰も確かめなくなる。また、取り出せない証憑は税理士へも税務署へも示せない。

背景: `docs/product/elegant-review-tax-preparation/` の T1〜T4（要件・体験・機能分解・リリース判定）。

# 非目標

1. 申告書・e-Tax送信データの生成
2. 税務上の適法性・控除可否の保証（減価償却・棚卸・青色申告特別控除・所得控除は計算しない）
3. freee内に既にある証憑原本の複製
4. パスワード・認証トークン・セッションの保存

# 到達状態

- 「確定申告の準備」で暦年1年を選ぶと、その年だけの準備チェック・転記シート・科目設定・証憑要約が
  1回の取得で揃う。画面に出ている対象年とAPIが読んだデータ範囲が常に一致する。
- 未割当の科目・未確認の按分・不足している証憑が、次の行動つきで先に並ぶ。
- 「領収書の残り」で未添付を優先度順に潰せる。スマートフォンではその場で撮って添付できる。
- 取得先（URL・サービス名・ログインに使うアカウント名・メモ）は取引先単位に1つ持ち、翌月以降へ
  既定で引き継がれる。明細だけの例外は明示行としてだけ持つ。
- 準備チェックを通過した年だけ、転記シートCSV・科目別経費内訳CSV・証憑ZIPが完成物として出る。

# 不変条件

## TI-1 対象年は暦年1年だけ

申告計算に入る期間は `2000..2099` の暦年1年に限る。分析用の全期間・直近年・任意期間は
400で拒否する。**申告用の画面・APIは分析用の期間セレクタを共有しない。**
理由: 期間の解釈が1箇所でもずれると、画面の年表示と金額の出所が黙って食い違う。

## TI-2 「未確認」は行の不在だけで表す

科目方針の正本は `user_id + tax_year + account`。**行が無いことだけを未確認とし、
全額事業でも `business_percent = 100` を明示保存する。**
理由: 既定値100%を暗黙に使うと、「確認して100%にした」と「まだ見ていない」が区別できない。

按分が100%未満のときは根拠（`basis`）を必須とする。転記先は経費用に許可された決算書科目だけを
受理し、収入科目・事業主貸は経費計へ入れない。専従者給与は経費計と分けて所得計算でだけ引く。

## TI-3 按分の端数は切り捨てる

`apportion` は絶対値で切り捨て、符号を保つ。
理由: 丸め誤差が経費を増やす側に働くと、誤差の分だけ申告額が過小になる。

## TI-4 割り当てのない科目は雑費へ寄せない

決算書科目が決まっていない帳簿科目は `unassigned` として金額つきで表に残し、
準備チェックの先頭へ出す。
理由: 「雑費」へ自動で寄せると、金額は合うが中身の説明ができない表になる。

## TI-5 添付済みはR2原本の存在で判定する

証憑の有無は D1 のmetadata件数ではなく、**exact-keyのR2 HEAD** で確かめる。
理由: metadataだけを見ると、原本が失われていても「添付済み」と表示され、
取り出せないZIPを完成物として返してしまう。

## TI-6 書き出しはサーバー側の準備チェックを最終ゲートにする

CSV・ZIPは、サーバーが再計算した準備チェックを通過した年だけ返す。
ZIPは対象年の事業支出に紐づくR2原本だけを、**索引と実ファイルが同一集合になる形**で生成する。
`RECEIPT_ZIP_MAX_FILES = 400` 原本を1分割とし、超過時は安定した複数partへ分ける。
欠損・取得失敗・不正partは無言で飛ばさず失敗させる。
理由: 「出たZIP＝揃っている」と読めなければ、書き出す意味が無い。

## TI-7 取得先に秘密値を持たせない

`source_url` は認証情報を埋め込まないHTTP/HTTPSだけを受理する。
サービス名・ログインに使うアカウント名（識別子）・メモは持てるが、
**パスワード・認証トークン・セッションは型・API・DB・バックアップのいずれの保存対象にも含めない。**
理由: 保存できてしまう場所を作ると、いつか誰かが入れる。

## TI-8 取得先は取引先単位の正本を1つだけ持つ

`ReceiptSourceProfile` の参照キーは `profile_key = merchant_key::service_key`。
同じ取引先に複数サービスを持てるが、**月ごとのコピーは作らない。**
継承は安全な表記揺れの範囲だけとし、複数候補がある場合は自動確定せず利用者に選ばせる。
理由: 月別コピーは更新漏れを生み、部分一致の自動継承は誤紐付けを作って回復しにくい。

## TI-9 証憑棚卸しは添付先の親取引へ正規化する

MFの分割記帳は子行を数えず、証憑の添付先である親取引へ1本化する。事業現金（freeeへ投影される
`cash_entries`）は棚卸しへ合流させる。freee側で記帳した仕訳の証憑は **freee側の確認対象** と明示し、
この画面では「未添付」と言わない。
理由: この画面で直せない対象を未対応として数えても、利用者は消せない。

## TI-10 家事按分の比率だけは 0..100 の整数

core・API・UI間の比率は原則 `1 = 100%` の小数だが、**利用者が入力・確認する `businessPercent` は
DB/API/core/UIを通して `0..100` の整数を正本とする。**
理由: 利用者が「30%」と入力した値を、保存と表示の往復で丸め直さないため。

# 未添付の緊急度

軸は2つだけ。**代替証憑があるか（支払手段）** と **金額の帯**。

| | < `RECEIPT_MINOR_AMOUNT`(3,000円) | 3,000〜29,999円 | ≧ `RECEIPT_MAJOR_AMOUNT`(30,000円) |
|---|---|---|---|
| 現金・支払手段不明 | 推奨 | **要対応** | **要対応** |
| カード・口座 | 後で確認 | 推奨 | **要対応** |

免除済み（電車代など `receipt_waived`）は金額によらず最下位に固定する。
**科目名は判定に使わない** — 利用者が自由に付けられる文字列なので、名前を変えた瞬間に
緊急度が静かに下がる。気づけない劣化は作らない。

しきい値は**作業順を決めるためのアプリ内の目安**であり、証憑の法的な要否判定ではない。

# 画面

## P16 確定申告の準備 `/tax`

並び順は 判定バナー → KPI → 準備チェック → 科目設定 → 転記シート → 書き出し。

- 対象年セレクタは申告専用。ヘッダーの分析用期間とは独立で、切り替えると全セクションが同じ年に揃う。
- 準備チェックは 要対応 → 確認 → 完了 の順に並べ、完了以外は必ず次の行動を持つ。
- 科目設定は「未設定だけ表示」に絞り込める。按分100%未満の行は根拠が空だと保存できない。
- 書き出しは要対応が残っている間は押せない。押せない理由を文字で示す。

## P17 領収書の残り `/tax/receipts`

- 初期表示は「要対応」。緊急度タブで絞り込め、件数と金額を常に表示する。
- 各行に「取得先を開く」「取得先を設定/編集」を置く。保存時の「今後の同じ取引先に使う」は既定ON。
- 継承元・明細上書き・曖昧候補を文字で示し、外部リンクであること・秘密を保存しないことを明示する。
- 作業中も対象年の準備チェックへ戻れる。
- モバイル下部タブに含める（申告期は最頻タスクになるため）。

# API

すべて認証ガード下。`year` は暦年1年（TI-1）。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/tax/overview?year=YYYY` | 準備チェック・転記シート・年別科目設定・R2証憑要約を1回で返す |
| PUT | `/api/tax/accounts?year=YYYY` | 対象年の科目方針を全置換保存。100%も明示値、100%未満は根拠必須、経費でない転記先は400 |
| GET | `/api/tax/receipt-gaps?year=YYYY` | R2原本未添付を優先度→金額順で返し、取得先の継承・候補・override状態を含める |
| PUT | `/api/tax/receipt-sources?year=YYYY` | 取得先の保存（同merchant継承・明細override・曖昧候補の明示選択） |
| GET | `/api/export/tax/statement.csv?year=YYYY` | 準備チェック通過時だけ返すBOM付き転記補助CSV。按分根拠と非保証注記を同梱 |
| GET | `/api/export/tax/expenses.csv?year=YYYY` | 準備チェック通過時だけ返す帳簿科目単位の科目別経費内訳 |
| GET | `/api/export/tax/receipts.zip?year=YYYY&part=N` | 全対象にR2原本が揃ったときだけ返す控え。`private, no-store` |

`packages/api/src/routes/tax.ts` は `Dataset` を `loadScoped`（`routes/analytics.ts`）経由でしか読まない。
この不変条件は `packages/api/src/analytics-period.test.ts` が機械的に検査する。

# 書き出しの形

## 転記シートCSV

列は `区分 / 決算書の科目 / 申告額 / 按分前 / 家事分 / 事業割合(%) / 内訳(帳簿科目) / 按分の根拠`
（`TAX_STATEMENT_EXPORT_HEADER` が正本）。1つの決算書科目に複数の帳簿科目が集まる場合、
事業割合が科目ごとに異なるなら `科目ごとに異なる` と出し、単一の数字で代表させない。
印字欄は青色申告決算書の並び、空欄行は金額の大きい順。未割当も行として出す。
表の末尾に空行を1行置き、以降に「減価償却・棚卸・青色申告特別控除・所得控除は計算していない」
旨の注意行を必ず付ける。

## 証憑ZIP

- `索引.csv` — 先頭3列は `取引年月日 / 取引金額 / 取引先`（電子帳簿保存法の検索要件そのもの）
- `YYYY-MM/日付_取引先_金額円[_連番].拡張子` — 月フォルダ。名前順がそのまま日付順になる
- `README.md` — 対象期間・件数・作成日時・探し方・非保証の注記

ZIPはstore方式（無圧縮）+ CRC32 + UTF-8ファイル名フラグ（bit 11）で、`TransformStream` により
逐次生成する。理由: Workerのメモリに全原本を載せない。

# 受入

- [ ] 全期間・任意期間・年跨ぎの `year` が400で拒否され、画面の年表示とデータ範囲が一致する
- [ ] 科目方針が行の不在だけで未確認となり、100%が明示保存される
- [ ] 按分100%未満で根拠が空なら保存できない
- [ ] 割り当てのない科目が雑費へ寄らず、準備チェックの先頭に金額つきで出る
- [ ] 収入科目・事業主貸が経費計に入らず、専従者給与が経費計と分かれる
- [ ] D1 metadataがあってもR2原本が無い明細は「添付済み」にならない
- [ ] 要対応が残る年ではCSV・ZIPが完成物として返らない
- [ ] 400件超の年でも全partが出て、各partの索引と実ファイルが同一集合になる
- [ ] `javascript:` 等の非HTTP(S) URLと認証情報付きURLが拒否される
- [ ] 他利用者のprofile/overrideを参照・更新できない
- [ ] backup/restoreで年別方針・取得先profile・明細overrideが復元され、秘密値の列が増えていない
- [ ] 同じ取引先の翌月の未添付に、取得先が再入力なしで引き継がれる
