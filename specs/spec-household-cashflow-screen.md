# 家計収支画面 再現仕様

`design/FINAL-UI/images/10-household.png` を読み取り、**同じ画面を再現できる**粒度まで
要素・文言・数値・状態・データ契約を確定した仕様。実装 (`packages/web/src/pages/household/`)
と core / API はこの文書を正本とする。上位概念 (U1-U9) の正本は
`system-spec/00-requirements-definition.md`。

画像はモックアップであり、算術が閉じない欄がある (§10)。**収入・支出を正本にし、差・率・構成比は
計算値にする** (利用者決定 qa-household-decision-006)。画像の値と計算値が食い違う欄は、
本仕様の表で計算値を期待値として示す。

## 0. 画面骨格

| 領域 | 扱い |
|---|---|
| 左サイドバー | **既存実装のまま**。`/household` の項目名だけ『家計収支』へ改める (§8) |
| ヘッダー (パンくず段) | 既存 `PageShell`。パンくずは `整える / 家計収支` |
| ヘッダー (期間段) | 既存の期間タブ (`usePeriod`)。`1年` `2年` `3年` `任意` と対象範囲 `2025年9月 - 2026年8月` |
| メイン | **本サイクルの作り直し対象**。カードを縦積み、中段は 2 カラム |
| 下部選択中バー | 画面下に固定。選択中の月を常に示す |
| フッター | 既存実装のまま |

メインの縦積み順 (上から):

1. 見出しカード (問い + 説明) と右上の『データの出典』カード
2. KPI 行 (総収入・総支出・純収支 + 前年より)
3. 月別の家計収支推移カード (タブ・凡例・棒と線・月送り) と、その下端の『事業と個人の内訳』
4. 2 カラム: 左『生活費カテゴリ別の内訳』表 / 右『カテゴリの詳細：<区分>』パネル
5. 3 カラム: 『名義別の収入』/『振替は収入・支出から除外』/『名義ラベルの設定』
6. 『前年との比較 (同じ期間・月次)』
7. 下部の選択中バー

狭幅 (既存のレスポンシブ規約の折り返し幅) では 2 カラム・3 カラムを縦積みにし、表は横スクロール
コンテナへ入れる。

色は既存トークンだけを使う。画像の緑 (収入・増加の良い向き) は `COLOR.accent` / 成功色、赤
(支出・悪化) は危険色、前年系列は同じ色の点線。直書き色を置かない。

## 2. 見出しカードと出典カード

### 2.1 文言 (完全一致)

- 見出し (h1): **家計の総収入・総支出・純収支は、どう変わりましたか？**
- 説明 (1 行): 収入・支出の推移から、家計の動きと変化の要因を確認しましょう。

### 2.2 データの出典カード (右上)

- 見出し: `データの出典`
- 本文: `<代表の取込元> 他<N>件` (例 `クレジットカード 他12件`)。代表は期間内の台帳行で
  **件数が最も多い取込元の種別**、N はそれ以外の取込元 (口座・カード) の数。取込元が 1 つなら
  `他N件` を出さない。
- リンク: `取込明細を確認 →` → `/import` (取込履歴)。

## 3. KPI 行

### 3.1 3 枚のカード

| カード | 見出し | 主値 | 下段 |
|---|---|---|---|
| 総収入 | `総収入（1年間）` | `¥6,480,000` | `月平均 ¥540,000` / `年換算 ¥6,480,000` |
| 総支出 | `総支出（1年間）` | `¥5,724,000` | `月平均 ¥477,000` / `年換算 ¥5,724,000` |
| 純収支 | `純収支（1年間）` | `+¥756,000` | `月平均 +¥63,000` / `年換算 +¥756,000` |

- 見出しの `（1年間）` は期間タブの表示名 (`1年間` / `2年間` / `3年間` / `期間内`) に従う。
- 月平均 = 合計 ÷ **記帳済みの月数** (未記帳月は分母に入れない。既存規約)。年換算 = 月平均 × 12。
- 純収支は符号を付ける (`+` / `−`)。総収入・総支出は符号を付けない。

### 3.2 前年よりカード

- 見出し `前年より`、主値は純収支の前年差 `±¥X` と率 `(±Y%)`、矢印 (増=上 / 減=下)。
- 文言: 純収支差 > 0 → `家計の黒字が増加しました。`、< 0 → `家計の黒字が減少しました。`、
  = 0 → `家計の収支は前年と同じです。` (純収支がマイナスの期間は `黒字` を `収支` と読み替えず、
  `家計の収支が改善しました。` / `家計の収支が悪化しました。` を使う)。
- 前年同期間に 1 か月でも欠けがあれば (総収支画面と同じ欠損規則 BR-006) 主値を `—`、
  文言を `前年の同じ期間のデータが揃っていません。` にする。
- **画像の `+¥120,000 (+18.9%)` は期待値にしない** (§10)。フィクスチャでの計算値は
  `−¥80,000 (−9.6%)` と `家計の黒字が減少しました。`。

## 4. 月別の家計収支推移カード

### 4.1 見出し行

- 見出し: `月別の家計収支推移`
- 右: 月送り `‹ 2026年8月 ›`。選択中の月を 1 か月ずつ動かす。期間の端で該当方向のボタンを
  `disabled` にする。

### 4.2 タブ (対象)

`家計全体` (既定・選択は accent 塗り + 白文字) / `事業` / `個人`。URL クエリ `seg=all|biz|personal`。
タブはグラフの系列だけを切り替え、KPI・内訳・表は常に家計全体を示す。

### 4.3 凡例 (5 系列・この順)

`収入（当期）` (塗りの棒) / `支出（当期）` (塗りの棒) / `純収支（当期）` (折れ線 + 点) /
`収入（前年）` (点線の枠の棒) / `支出（前年）` (点線の枠の棒)。

### 4.4 グラフ

- 縦軸の単位 `(万円)`、0 起点。横軸は期間内の月 (`9月` … `8月`)。年の変わり目の月にだけ年を添える
  (`9月 2025`、`1月 2026`)。
- 選択中の月は列全体を淡い帯で強調し、月ラベルを太字にする。
- 月の棒をクリック (またはキーボードで選択) するとその月を選択する。月送りと同期する。
- 前年系列は前年同月の実データがあるときだけ描く。期間外 (表示期間より前) の実データも参照する。
  無い月は描かない (0 として描かない)。
- 既存の `FinancialFigure` と系列色の定義 (`packages/web/src/components/charts.ts`) を使う。

### 4.5 事業と個人の内訳 (カード下端)

- 見出し: `事業と個人の内訳` + 注 `（家計全体の内訳・重複なし）`
- 左: `事業の純収支 +¥571,000` と `（総収入の35.1%）`
- 中: `個人の純収支 +¥185,000` と `（総収入の64.9%）`
- 右: 等式 `家計全体の純収支 ¥756,000 = 事業 ¥571,000 + 個人 ¥185,000`
- 注記: `※ 事業と個人は別会計として集計しており、金額の重複はありません。`
- 括弧内の率は **その区分の収入 ÷ 家計全体の総収入** (見出しの語『総収入の』に従う)。2 つの率の
  和は 100.0% (丸めで 99.9 / 100.1 になる場合は大きい剰余の側で寄せない。各率を独立に丸める)。
- **等式は core が保証する不変条件**: 全月・期間合計で `事業 + 個人 = 家計全体` (収入・支出・純収支の
  それぞれ)。

| 区分 (key) | 表示名 | 含める台帳行 |

| カテゴリ | 当期 | 前年 | 増減額 | 構成比 (計算値) | 画像の構成比 |

| 住居費 | ¥1,440,000 | ¥1,380,000 | +¥60,000 | **25.2%** | 25.1% |

## 6. 名義別の収入 / 振替 / 名義ラベルの設定

### 6.1 名義別の収入

列: `名義` / `当期` / `前年` / `増減額`。行は表示名の順 `本人` `パートナー` `子ども` `その他`、最終行 `合計`。

| 名義 | 当期 | 前年 | 増減額 |
|---|---|---|---|
| 本人 | ¥3,600,000 | ¥3,480,000 | +¥120,000 |
| パートナー | ¥2,640,000 | ¥2,520,000 | +¥120,000 |
| 子ども | ¥240,000 | ¥200,000 | +¥40,000 |
| その他 | ¥0 | ¥0 | 0 |
| 合計 | ¥6,480,000 | ¥6,200,000 | +¥280,000 |

- 名義の決め方: freee 由来の行 (事業) は `business` (本人)。MF 由来の行は公私仕分けと同じ
  `resolveTx` の `owner` (未解決は `unset` → その他)。**合計 = 総収入** (不変条件)。
- 収入の増加は成功色、減少は危険色。0 は符号なしの `0`。

### 6.2 振替は収入・支出から除外

- 見出し: `振替は収入・支出から除外` (アイコン ⇄)
- 説明: `同一名義間・名義間の資金移動（振替）は、家計の収支に影響しないため、収入・支出から除外しています。`
- `除外した振替 (2026年8月)`。選択月の振替をこのカード内に**全件 (抜粋なし)**表示する。
  この一覧自体が全件表示なので、同じ振替を再表示する `すべて見る` 導線は置かない。
- 列: `日付` / `内容` / `金額` / `名義間`。

  | 日付 | 内容 | 金額 | 名義間 |
  |---|---|---|---|
  | 8/10 | 本人→パートナー | ¥50,000 | 本人 → パートナー |
  | 8/18 | パートナー→本人 | ¥30,000 | パートナー → 本人 |

- 1 行 = 対推定で 1 組になった振替 (出金側と入金側の 2 明細)。金額は絶対値。対にならない明細は
  1 明細 1 行で、名義間を `<名義> → 相手不明` (出金側) / `相手不明 → <名義>` (入金側) とする。
- **対推定の規則** (core の純関数、決定論) (agent 推定・利用者未確認。根拠 `qa-household-backend-web-003`):
  1. 対象は期間内の MF 明細で `isTransfer === true` のもの (現金明細・分割の派生行は除く)。
  2. 候補の組 = 金額の絶対値が等しく、符号が逆で、日付差が `TRANSFER_PAIR_MAX_DAYS = 3` 日以内。
  3. 組は日付差の小さい順、同差なら出金側の日付の昇順、さらに同じなら明細 id の昇順で貪欲に確定し、
     1 明細は 1 組にしか入らない。
  4. 名義は各明細の `resolveTx(...).owner`。同じ名義どうしの組も表示する (`本人 → 本人`)。
- **振替の合計は総収入にも総支出にも 1 円も入らない** (台帳は `isMfCountable` で振替を除く。
  core のテストで固定する)。

### 6.3 名義ラベルの設定

- 見出し: `名義ラベルの設定` (人のアイコン)
- 説明: `収入・支出の名義（本人・パートナーなど）の設定・編集ができます。`

### 11.3 `GET /api/settings/owner-labels` / `PUT /api/settings/owner-labels`

### 11.4 migration (追加のみ)

次の空き番号 (実装時に origin/main を fetch して確定する。並行ブランチと番号が衝突しうる) で
`owner_labels` 表を新設する。既存表の行を 1 行も書き換えない。

```sql
CREATE TABLE owner_labels (
  user_id    TEXT NOT NULL,
  owner      TEXT NOT NULL CHECK (owner IN ('business', 'spouse', 'family', 'unset')),
  label      TEXT NOT NULL CHECK (length(label) BETWEEN 1 AND 20),
  updated_at TEXT NOT NULL,
  PRIMARY KEY (user_id, owner)
);
```

- 行が無い名義は既定の表示名 (§6.4)。表が空でも画面は動く (初期データを投入しない)。
- `runtimeSchemaGuard` の必須表へ追加し、未適用の環境では既存の 503 契約で止める。

## 12. 集計規則 (core `household-summary.ts`)

- 入力は `totalCashflowLedger(all, deals, verdicts, exclusions, mfExcludedTxIds)` の `ledger.rows`。
  家計画面が独自の選別を持たない (総収支画面・推移画面と同じ行集合)。旧 `household()` と
  `HouseholdData` は削除し、利用箇所をこの関数へ移す。
- 台帳行に名義 (`owner: Owner | 'unset'`) を追加する (freee 行は `business`、MF 行は `resolveTx` の owner)。
  既存の利用者 (総収支・推移) は名義を読まないので数値は変わらない。
- 区分: `side === 'business'` → 事業、`side === 'household'` → 個人。
- 前年: `previousYearPeriod(range)` の月がすべて既知のときだけ算出する。
- 未記帳月は平均の分母に入れない。
- 不変条件 (テストで固定):
  1. `summary.total` = 総収支画面 (`totalCashflowScreen`) の同期間の `summary.total`。
  2. 全月で `biz + personal = total` (収入・支出・純収支)。
  3. `categories` の当期の和 = `summary.total.expense`。
  4. `owners` の当期の和 = `summary.total.income`。
  5. 振替 (`isTransfer`) の明細は `ledger.rows` に 1 件も現れない。

## 13. 受入 (画像再現テスト)

1. §3〜§7 のフィクスチャを流し込むと、KPI・内訳・カテゴリ表・名義別収入・前年との比較が本仕様の表
   (§10 の計算値を含む) と一致する。
2. 同じ Dataset と期間で、家計画面の家計全体と総収支画面の総合が `toBe` で一致する。
3. `食費` を選ぶと詳細パネルが `¥960,000` / `前年比 +¥120,000 (+14.3%)` を出し、
   期間合計 `current = 960000`、選択月合計 `monthTotal = 80000`、全 6 件中の 5 件プレビューを別物として保つ。
   `すべて見る` が `/classify?month=2026-08&big=食費` を指す。
4. 選択月の振替がカード内に全件 (抜粋なし) 出て、振替用の `すべて見る` 導線が無い。
   `本人 → パートナー` / `パートナー → 本人` の金額は総収入・総支出に含まれない。
   相手の無い振替は `相手不明` と出る。
5. 名義ラベルを `わたし` に変えると、家計・設定・明細の名義表示が `わたし` になる。21 文字と制御文字は 400。
6. URL は `seg` / `month` / `cat` のみを持ち、期間タブは `usePeriod` / localStorage からリロード復元する。
7. 選択期間の集計対象台帳行 0 件で空状態カードが出て `データ取込へ` が `/import` を指す。
   振替のみ、除外行のみでも空状態になる。前年欠損で前年欄が `—` になる。
8. 直書き色 0 件。ナビとパンくずが `家計収支`。既存の総収支・推移・マトリックス・分析ハブのテストが緑で、
   初期 JS 予算を超えない。

受入は実行済みの最新のテスト証跡だけで判定する。未実施、一部適合、または既知の逸脱が 1 件でも残る項目は PASS にしない。
