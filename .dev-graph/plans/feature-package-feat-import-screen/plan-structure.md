## このタスクの目的と、導入で得られる価値

### 技術的な詳細 (エンジニア向け)
- **目的 (何をするか)**:
  - データ取込画面を
  - 利用者 (個人事業主とその家族の家計を 1 人で管理する本人) が freee (事業) と マネーフォワード (家計) から書き出した複数の明細ファイルをまとめて選び
  - 確定する前にファイルごとの取込元・対象期間・大きさ・重複・検証の結果と取り込み予定の要約を確かめ
  - 取り込めるファイルだけを確定し
  - 結果から次の画面へ進み
  - 過去の取込を 1 回ごとに振り返って原本の取得・再取込・取り消しを決着できる場にする誤った取込や二重取込で台帳を壊さないこと
  - 取り込んだデータを外部へ送らないことを守る
- **到達状態 (Goal)**: /import が 16-import.png の構成 (問いの見出し・期間タブ・対象期間カード・3 段のステッパー・1.ファイルを選択・2.取込ファイル一覧 (9 列)・3.取込内容の確認 (要約 6 項目と除外の注記)・4.取込結果 (4 枚のカード)・5.取込履歴 (7 列) と履歴の詳細ペイン・下部の選択件数バー・読込 / 空 / 失敗) をトークンと共通部品で描画し、検査 (R2 の 24 時間仮置きとファイルごとの検査結果) と確定 (検査 ID 指定) の 2 段階で検査中の台帳書き込みが 0 件になり、ファイルの状態・検証の段階・取込可否・要約・取込 1 回の結果・上限値 IMPORT_LIMITS と超過理由の判定が packages/core/src/import-screen.ts の 1 か所で導かれて web の送信前判定と api の 413 が同じものを import し、『前回データを残す』が既定オンの行単位の追加になり、取込履歴が取込 1 回ごとの 1 行と影響の 3 数値を持ち、上限・同一オリジン・取込専用のレート制限の拒否がテストで固定され、追加のみの migration (0050 以降) で既存の取込履歴と取り消し・破棄の挙動を失わずに Import.tsx が分割された状態。
