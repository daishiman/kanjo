## このタスクの目的と、導入で得られる価値

### 技術的な詳細 (エンジニア向け)
- **目的 (何をするか)**:
  - 明細仕分け画面で選んだ明細を
  - 提案の有無や表示中のページ・絞り込みに左右されずに
  - 何がどの値で保存されるかを確かめたうえで一括で確定できるようにする取込直後で取引先の記憶もルールも無い利用者でも未整理を月次クローズまで減らせるようにし
  - 『選んだのに保存できない』『再試行を押しても何も起きない』『一覧が崩れて読めない』ことで仕分けが止まるのを無くす
- **到達状態 (Goal)**: /classify で、提案の無い明細も一括指定欄で値を決めて保存でき、保存前の内訳で保存する件数と外す件数を確かめられる。選択は URL の sel に行の key で保たれ、サーバが明細を引き直して 1 回の batch (D1 クエリ 49 本以内) で書き、再試行は write_failed の明細と要求全体の失敗 (通信の失敗・5xx・409) にだけ出る。取込直後でも『MF の分類』の提案が付き、勘定科目の対応表を設定画面で編集でき、取引一覧は 1264px でも 6 列で崩れない。lint・typecheck・test・skills:test・初期 JS 予算・verify:full は緑のまま。
