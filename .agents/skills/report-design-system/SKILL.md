# レポート用デザインシステム

「読ませる文書」（分析レポート・報告書・手順書・設計書）専用のデザイン。実案件で発注者検収済み。**アプリのUIには使わない**（画面を操作するものは Skill `jp-web-design`）。

正本は `assets/report.css`（全CSS）と `assets/template.html`（骨格＋全コンポーネントの使用例）。**新しいレポートは必ずtemplateをコピーして始める。記憶で似せて書かない。**

## 0. 絶対原則

1. **単一HTMLファイル・外部参照ゼロ。** CDN・Webフォント・画像リンクを使わない。SVGもJSもファイル内に埋める。メール添付・USB・ダブルクリックで完全に動くこと。
2. **白背景固定。** ダークモードは作らない。印刷・投影・社内共有が前提。
3. **色は意味にだけ使う。** 赤（--danger）=損失・悪化・赤字／青（--brand）=主役・構造・黒字／グレー=脇役・現状／橙（--accent）=**結論のキー数字専用で1文書1〜2箇所まで**。装飾のための色は使わない。
4. **数字はすべて実データの計算結果。** 演出のための数字・概数での誤魔化しをしない。出所をfooterに書く。
5. 本文幅は `max-width:1020px`。表・チャートは自身のコンテナ内で横スクロール（`overflow-x:auto`）させ、ページ全体を横スクロールさせない。

## 2. コンポーネントカタログ（詳細はtemplate.htmlの実例を見る）

| クラス | 用途 | 使い所の規律 |
|---|---|---|
| `header.doc` + `.crumb` + `h1` + `.sub` | 文書ヘッダー（下線3px） | h1は「題名 — 結論の副題」。subに対象データ・件数・日付 |
| `.secno` | セクション番号チップ | 「結論」「DATA」「分析 1」「ACTION」「まとめ」など |
| `.hero` | ヒーロー数字カード列 | 結論とまとめに3〜4個。`.v.red/.blue/.acc`で意味色 |
| `.method` | 仮説→手法→結果→前提と限界 | 分析セクションの冒頭に必ず置く（4点セット） |
| `figure` + `.chartbox` + `svg.chart` | チャート | figcaptionに題名+凡例。SVGは§3の規範 |
| `.tblwrap` + `table` | 表 | 数値列は`th.r`+`td.r`右揃え、**単位は列ヘッダー**、1列1単位。記入例行は`td.ex` |
| `.typecards` (`.tc.good/.bad`) | 型の対比カード | 高収益型/低収益型のような2×2まで |
| `.actions` (`.act`+`.who`) | 連番アクション+担当チップ | 動詞で始まる指示文+根拠1行 |
| `.rules` (`.rule`) | 原則の連番ボックス | 「記録の4原則」のような規律の列挙 |
| `.say` | 現場に伝える言葉（青帯） | 朝礼でそのまま読める文。統計用語禁止 |
| `.guard` | やってはいけないこと（黄帯） | ガードレール・よくある失敗 |
| `.kpi` | 小型KPI帯 | 施策カードの頭に「67% → 50%」のような数字 |
| `.pill` (`.bad/.info/.warn/.plain`) | タグ | 意味は文書内で固定（例: bad=修繕、info=空き） |
| `.loss` / `.profit` | 金額の色 | ▲表記とセットで。マイナス記号でなく▲ |
| `footer` | 出所 | データファイル名・手法・「数値はすべて実データからの計算結果」 |

## 3. SVGチャートの規範

- **外部ライブラリを使わない。** SVGを直書き（生成スクリプトで組み立ててよい）。
- viewBox幅は760〜960。`svg.chart`は`width:100%; min-width:640px`で、狭い画面はchartbox内スクロール。
- テキストは共通クラスで統一: `.ax`(軸・11px) `.lb`(項目・12px) `.vl`(値・太字) `.vl2`(副の値) `.an`(図中注記)。
- **色**: 脇役・比較対象=グレー(#8b94a1)、主役・今期=--brand、悪化・赤字=--danger。凡例か直接ラベルを必ず付ける。
- 棒・点・線の要素に `data-tip="車番◯◯: 値"` を付ける（テンプレート末尾のツールチップJSとセット。マウスで詳細が読める）。
- 使う形は原則4種: **ウォーターフォール**（差の分解）／**単月棒+移動平均線**（ブレと実力）／**ストリップ・散布**（分布と外れ値）／**ダンベル・レンジバー**（2時点・2群の比較）。**円グラフ・二軸・3Dは使わない。**
- 軸ラベルの衝突・「1文字だけ改行」をレンダリングで実際に確認してから完成とする（スクリーンショット検証）。

## 4. 文章の規律

- **見出し（h2）は結論を文で書く。**「分析結果」ではなく「儲かる車と儲からない車を分けているのは距離とリースだった」。
- `.lede`で見出しの補足を1行。本文の太字は**数字と結論だけ**。
- 事実と解釈を語尾で書き分ける（事実=「67%である」、解釈=「〜が原因とみられる」）。
- 分析セクションは method（仮説→手法→結果→前提と限界）を必ず添え、**手法を選んだ理由と言えないことまで書く**。
- 対策には「やらないことリスト」（データで否定された打ち手）を含める。
- 比喩・キャッチコピー・煽り・絵文字は使わない。1文50字以内を目安。

## 5. 使い方の手順

1. `assets/template.html` をコピーし、`<style>`に `assets/report.css` 全文を貼る。
2. `<title>`（名詞句2〜4語）・crumb・h1・subを書く。
3. セクションを組む。標準構成: **結論（hero）→ DATA（元データの紹介）→ 分析1..n（method+figure+解釈）→ 類型（必要なら）→ ACTION → まとめ（hero再掲+訴求）→ footer**。手順書なら施策カード（kpi+手順+say+guard）構成。
4. チャートはPython等でSVG文字列を生成して埋め込む（数値の手打ちをしない）。
5. ヘッドレスブラウザでスクリーンショットを撮り、ラベル衝突・折返し・はみ出しを目視確認してから納品。

## 6. 検収チェックリスト

- [ ] 単一ファイルで外部参照ゼロか（`grep 'src="http\|href="http\|@import'` が0件）
- [ ] 白背景・色は意味のみ・accentは2箇所以下か
- [ ] 数字がすべて`.num`系（欧文・tabular）で描画されているか。表は右揃え+単位ヘッダーか
- [ ] 各分析にmethod（仮説/手法/結果/限界）が付いているか
- [ ] チャートに凡例または直接ラベル、data-tipがあるか。円グラフ・二軸がないか
- [ ] 見出しが結論文になっているか。比喩・絵文字がないか
- [ ] footerにデータの出所と手法があるか
- [ ] レンダリング確認（スクリーンショット）を実施したか
